# manager: данные доменов, ЕСИА и смена владельца ЛК (расширение Chrome)

С версии 0.3.0 PySimpleManager умеет сам получать из manager данные доменов из заявления:

- **Sd** - администратор домена;
- **S** - поле `provider` (текущий регистратор) и номер аккаунта;
- **ЕСИА** (с 0.6.0; юрлица - с 0.7.2) - идентификация администратора домена через Госуслуги: поле `state` и сверка Sd с файлом данных ЕСИА.

Дальше эти данные сверяются с паспортом и заявлением. С 0.6.0 есть вкладка **«Смена владельца ЛК»**: базовая анкета аккаунта, сверка с заявлением и автозаполнение анкеты данными нового владельца (раздел 5). Работает только в **веб-интерфейсе** (`doctool_web.bat`).

Данные из manager читает расширение Chrome «PySimpleManager». Оно работает в вашем Chrome, от вашего входа в manager, и делает то же, что вы делаете руками:

1. ищет домен в поле «Позиция»;
2. открывает Sd;
3. открывает S;
4. (физлица) открывает «Идентификация через Госуслуги» со страницы Sd и файл по ссылке «Смотреть файл».

Расширение ничего не нажимает и ничего не сохраняет в manager. Единственное, что оно меняет, - значения полей в форме базовой анкеты по кнопке «Заполнить автоматически» (раздел 5); «Сохранить» нажимаете вы. С 0.7.6 - ещё поля страницы «Перенос доменов между аккаунтами» и формы «Проверка действительности паспорта» на Госуслугах по кнопкам рабочего места (раздел 5а); «Далее» и «Продолжить» нажимаете вы.

## 1. Установка (один раз)

1. **Обновите зависимости** (только при запуске из исходников; установленной программе с 0.7.5 не нужно - всё внутри).
   В 0.3.0 добавился пакет `websockets`; с 0.7.4 файл зависимостей веб-интерфейса называется
   `requirements-web.txt` (раньше - `requirements-gui.txt`). В папке программы выполните:

   ```
   py -3.12 -m pip install -r requirements.txt -r requirements-web.txt
   ```

2. **Установите расширение в Chrome:**
   1. Откройте адрес `chrome://extensions`.
   2. Справа вверху включите **«Режим разработчика»**.
   3. Нажмите **«Загрузить распакованное расширение»** и выберите папку расширения:
      - установленная программа (с 0.7.5) - `chrome_extension` в папке программы: Windows - Пуск → PySimpleManager →
        «Расширение Chrome (папка)» (`%LOCALAPPDATA%\Programs\PySimpleManager\chrome_extension`), Linux -
        `/opt/pysimplemanager/chrome_extension`; там же `КАК_УСТАНОВИТЬ.txt`;
      - запуск из исходников - `doctool_extension` из архива или репозитория программы.
   4. Появится карточка «PySimpleManager» с версией расширения. Нажмите на значок-пазл на панели Chrome и закрепите значок расширения (синий квадрат с буквой «d»).

   Не удаляйте и не перемещайте папку расширения: Chrome загружает расширение прямо из неё. Установщик новой версии
   кладёт расширение в ту же папку - после обновления достаточно нажать ⟳ на карточке. Если папку переместили, удалите расширение и загрузите его заново из нового места.

3. **Запустите программу PySimpleManager:** ярлык «PySimpleManager» (установленная программа) или `doctool_web.bat`. Через несколько секунд:
   - в шапке веб-интерфейса появится зелёная точка и надпись «manager: расширение подключено»;
   - на значке расширения пропадёт красный «!».

4. **Войдите в manager в этом же Chrome**, как обычно.

После обновления файлов расширения откройте `chrome://extensions` и нажмите ⟳ на карточке «PySimpleManager» (до 0.7.1 - «doctool - manager»). В 0.6.0 расширению нужен ещё доступ к `https://identity.reg.ru/` (там лежат файлы данных ЕСИА), с 0.7.6 - к `https://www.gosuslugi.ru/` (проверка паспорта из рабочего места): если Chrome спросит разрешение - разрешите. Расширение 0.7.6 нужно для кнопок рабочего места; программа 0.7.6 со старым расширением загружает домены как раньше, а на кнопки рабочего места отвечает «неизвестная команда». Страницы manager, открытые до обновления, лучше обновить (F5).

## 2. Как пользоваться

Вкладка **«Домены в manager»** (до 0.8.1 - блок вкладки «Проверка заявления и домены») или окно «Домены» рабочего
места: впишите домены через пробел, запятую или с новой строки и нажмите **«Загрузить данные из manager»**. В рабочем
месте домены из заявления подставляются и загружаются сами после проверки дела, данные Sd сверяются с документами.

Таблица доменов занимает всю ширину окна браузера: длинные имена доменов, e-mail и «кем выдан» переносятся, прокручивать вбок не нужно.

## 3. Что показывается

| | Физлицо (ru_pp) | Юрлицо (ru_org) |
|---|---|---|
| Из Sd | ФИО, дата рождения, серия и номер паспорта, дата выдачи, кем выдан, страна, дата последней смены администратора (`last_admin_change`), e-mail (`e_mail`) | название организации (`org_r`), ИНН (`code`), страна, дата последней смены администратора, e-mail (`e_mail`) |
| Из S | `provider` - текущий регистратор, `user_id` - аккаунт, в котором лежит домен | то же |

Ещё в таблице:

- статус услуги из Sd («Активна (A)»);
- ссылки **Sd** и **S**: открывают эти страницы manager в новой вкладке.

Если поля `last_admin_change` в Sd нет, в таблице стоит «-».

**С 0.7.6:** под номером аккаунта - **логин** аккаунта (со страницы S). Если в S заполнено поле «Комментарий
администратора» (`admin_comment`), рядом с доменом стоит буква **«К»**: щелчок - окошко с текстом комментария и
кнопкой «Копировать». Поле `comment` (комментарий клиента) не читается. **Проверки домена** - комментарий
администратора, недавняя смена администратора, запреты в S (`clientHold`, `serverHold`, `*Prohibited`), заморозка,
блокировки операций, запрет переноса, услуга не активна, срок регистрации, Trustee, нет идентификации через
Госуслуги, владелец счёта - другой аккаунт - с уровнем «стоп» / «внимание» / «к сведению»; уровни и сроки - в
`config/workspace.yaml` (раздел `domain_checks`). На вердикт они не влияют.

**Домен не найден в manager.** В таблице стоит «не найден», и PySimpleManager делает **WHOIS-запрос**: свободен ли домен, у какого регистратора и до какой даты оплачен. Если WHOIS недоступен (в сети закрыт порт 43), рядом будет ссылка для ручной проверки.

**Порядок строк - по «проблемности»** (с 0.4.0). Домены разбиты на группы, у каждой - заголовок с числом доменов:

| Группа | Когда |
|---|---|
| Свободен по WHOIS | в manager не найден, WHOIS: домена нет в реестре |
| Данные в Sd не сходятся с документами | в Sd другое ФИО, дата рождения, паспорт другого человека или другой ИНН |
| Нет в manager | в manager не найден, WHOIS: занят у другого регистратора или WHOIS не проверялся |
| Данные из manager не получены | ошибка, таймаут, нет входа в manager, загрузка остановлена |
| Нужна ручная сверка | домен на юрлицо, неуверенное сходство ФИО, неизвестный тип контактов |
| Мелкие расхождения | тот же паспорт, но другая дата выдачи или «кем выдан» |
| К сведению | например, в Sd прежний паспорт, подключён Trustee |
| Найден, сверка не выполнялась | данные загружены кнопкой до проверки дела |
| В порядке | всё совпало |

Внутри группы домены идут в порядке заявления. Тот же порядок - в разделе «Домены в manager» файла `report.html`. В `export.json` (`manager_domains`) порядок - как в заявлении, у каждого домена есть поля `problem` (код группы), `problem_ru` и `problem_rank`. В комментарии проверки «Домены в manager» свободные домены тоже перечисляются первыми. Группы задаются в `doctool/domains.py` (`PROBLEMS`).

**E-mail администратора** (с 0.5.0). В таблице и в отчётах под ФИО/названием администратора: для .RU/.РФ/.SU - поле `e_mail` из Sd, для остальных зон - `o_email`. Если адресов несколько (по строке на адрес), показываются все.

### ЕСИА - идентификация через Госуслуги (с 0.6.0; юрлица - с 0.7.2)

Для доменов физлиц (`ru_pp`) и, с 0.7.2, юрлиц (`ru_org`) расширение открывает ссылку **«Идентификация через Госуслуги»** со страницы Sd этого домена. Идентификация относится к администратору домена (у физлица ссылка ведёт на `?user_id=…`, у персоны - на `?person_id=…`), а не к аккаунту: владелец аккаунта может не быть администратором домена. Если записей несколько, берётся последняя по дате создания.

- Колонка **«ЕСИА»**: значение `state` (например, `approved`) и итог сверки: «Sd = ЕСИА (9 из 9)», «Sd ≠ ЕСИА: Дата выдачи», «не проходил» (записей нет), «нет файла данных», «нет ссылки на Sd», «ошибка: …».
- Кнопка **ESIA** рядом со ссылками Sd / S (у всех найденных доменов физлиц и юрлиц) открывает окно сверки: state, даты, action, ссылки на страницу идентификации и JSON-файл, и таблица. Если сверки нет, окно объясняет почему (записей нет, нет ссылки, файл не загрузился).

Физлицо (`ru_pp`):

| Sd | ЕСИА (JSON) | Как сравнивается |
|---|---|---|
| `person_r_surname` | `last_name` | без регистра, ё/е, пробелов, знаков препинания |
| `person_r_name` | `first_name` | так же |
| `person_r_patronimic` | `middle_name` | так же |
| `birth_date` | `birth_date` | дата |
| `country` | `citizenship` | код страны: RU = RUS |
| `passport_series` | `rf_passport.series` | цифры |
| `passport_number_short` | `rf_passport.number` | цифры |
| `passport_date` | `rf_passport.issue_date` | дата |
| `passport_place` | `rf_passport.issued_by` | одинаково → зелёный; похоже (≥ 85 %), но написано по-разному → жёлтый |

Юрлицо (`ru_org`, с 0.7.2):

| Sd | ЕСИА (JSON) | Как сравнивается |
|---|---|---|
| `code` | `inn` | цифры |
| `kpp` | `kpp` | цифры |
| `org_r` | `full_name` | организационно-правовая форма сокращением = полностью: ООО = «Общество с ограниченной ответственностью», АО / НПАО / НАО = «(Непубличное) акционерное общество», ОАО = «Открытое акционерное общество», ПК = «Производственный кооператив», «Хозяйственное товарищество» = полное товарищество / товарищество на вере (а также ЗАО, ПАО, ОДО, АНО, ФГУП, ГУП, МУП). Название (в кавычках) должно совпасть без учёта регистра, кавычек и знаков препинания. Разная форма (ООО ≠ АО, ОАО ≠ ПАО) → красный; форма указана только с одной стороны → жёлтый |
| `address_r_street` | `legal_address.street` | тип улицы сокращением = полностью («ул.» = «улица», «пр-кт» = «проспект»…), название - без регистра и знаков. Другой тип улицы или похожее название (≥ 85 %) → жёлтый |
| `address_r_house` | `legal_address.house` | «11» = «Д. 11» = «дом 11»; корпус и строение, если в Sd они в отдельных полях (`address_r_frame`, `address_r_building`), тоже учитываются. Совпал только номер дома → жёлтый |
| `address_r_zip` | `legal_address.zip_code` | цифры |

Если по данным ЕСИА организация ликвидирована (`is_liquidated`), в окне - красная строка «Организация действует: ликвидирована». В окне также ОГРН и юридический адрес из ЕСИА целиком (для сведения, не сверяются).

Зелёный - совпадает, красный - расходится. Если значения нет с одной из сторон - без цвета («нет в ЕСИА»). **На вердикт дела ЕСИА не влияет**; в выгрузке по доменам - колонка «ЕСИА», то же окно ESIA (встроено в файл) и строка в «К сведению».

Страница идентификации и файл ЕСИА одной персоны в пределах одной загрузки читаются один раз (у 500 доменов одного администратора - один запрос).

### MO - администратор домена ↔ владелец аккаунта (с 0.8.4)

Колонка **«MO»** (matches owner, «matches account owner contacts») и кнопка **MO** у домена: совпадает ли администратор
домена (Sd) с владельцем аккаунта, в котором домен лежит (базовая анкета). Анкету расширение берёт со страницы «Данные
пользователя» аккаунта из S (её же - для e-mail аккаунта, раз на аккаунт), если блока анкеты нет - из формы
`/user/N/runic_details`. Сверяются у физлица ФИО, дата рождения, гражданство, серия и номер (в Sd - отдельно, в анкете -
10 цифр), дата выдачи, кем выдан, ИНН, телефон, e-mail, индекс, город, почтовый адрес (в Sd - по полям, в анкете -
строкой); у юрлица - название, ИНН, КПП, страна, юридический и почтовый адрес, телефон, e-mail. Телефоны и e-mail
совпадают, если есть общий. Администратор - физлицо, а аккаунт на юрлице (или наоборот) - «Sd ≠ анкета». Поле manager
`matches_user_contacts` из Sd показывается в окне для справки. Окно и цвета - как у ESIA; на вердикт не влияет.

**Остальные зоны** (.com, .москва и т. п.). Администратор (владелец) - группа `o_*` в Sd (`o_deti_org`, `o_gtld`…): показываются организация (`o_company`) или ФИО, страна (`o_country_code`) и e-mail. Автоматической сверки с паспортом для них нет - «нужна ручная проверка».

### Выгрузка по доменам (HTML)

Кнопка **«Выгрузка по доменам (HTML)»** в блоке «Домены в manager» (активна, когда таблица заполнена). Скачивается один HTML-файл без внешних ссылок - его можно переслать:

- итог по группам «проблемности» (со ссылками на группы);
- проверки: если домены загружены после проверки дела - проверки дела по доменам (в т. ч. сверка Sd с заявлением и паспортом); если без дела - «Домены в manager» и «Администратор у доменов один»;
- администраторы найденных доменов: ФИО/организация, паспорт или ИНН, e-mail, статусы услуг, аккаунты, число доменов;
- «к сведению»: статусы услуг (приостановлена, удалена), разные администраторы в одном аккаунте, один и тот же паспорт с разными «кем выдан»/датой выдачи в Sd, не найденные домены, похожие на найденные (вероятная ошибка распознавания: `vstshakii.ru → vst-shakti.ru`), несуществующие зоны, «найдено несколько услуг»;
- таблица доменов с фильтром (домен, ФИО, паспорт, ИНН, e-mail, provider), ссылками на Sd/S/счета и WHOIS. С 0.7.2 `provider` - отдельная колонка; таблицу можно сортировать щелчком по заголовку любой колонки (повторный щелчок - обратный порядок, пустые значения - в конце), кнопка «По группам» возвращает исходный вид по «проблемности».

Для дела файл также сохраняется в его папку - `domains.html` рядом с `report.html`.

**Несуществующая зона** (с 0.5.0). Если зоны нет в корневой зоне IANA (например, «chi.pd» - ошибка распознавания «.рф»), WHOIS даёт «ошибка: зоны .pd не существует», а не «свободен».

## 4. Как сверяется и как влияет на вердикт

| Проверка | Как | Итог |
|---|---|---|
| **Домены в manager** | все домены из списка найдены? | не найден → «расхождение» → «Ручная проверка» (причина: «Домен из заявления не найден в manager») |
| **Заявитель - администратор доменов (Sd)** | ФИО и дата рождения в Sd ↔ паспорт (если паспорта нет - заявление) | совпали → «в порядке»; другое лицо → «расхождение» → **«Отклонить»** («Заявитель не является текущим администратором домена»); похоже, но не точно или домен на юрлицо → «нужна ручная проверка» |
| **Паспорт в Sd** | серия и номер; если паспорт тот же - ещё дата выдачи и «кем выдан» | другой номер при совпадающих ФИО и дате рождения → «к сведению» (в Sd старый паспорт, его нужно обновить); тот же паспорт, но другая дата или «кем выдан» → «проверить» |
| **Администратор у доменов один** | у всех найденных доменов один администратор (по паспорту / ИНН) | разные → «проверить» |

Латиница из Sd (`person_surname` и т. п.) не сверяется: в manager встречаются разные варианты транслитерации.

## 5. Смена владельца личного кабинета (с 0.6.0)

Вкладка **«Смена владельца ЛК»** в веб-интерфейсе (с 0.8.5 - и окно «Смена владельца ЛК» в рабочем месте, то же самое). Физлица, с 0.7.3 - ИП и юрлица.

**1. Аккаунт.** В поле «Пользователь» можно вставить: номер аккаунта; «Данные пользователя #15904265» или «Базовая анкета пользователя #15904265» (заголовок страницы manager); ссылку из manager (`…user_details?user_id=…`, `…/user/…/runic_details`); «договор № …»; логин; домен - тогда номер аккаунта берётся из S (владелец услуги), а если владелец счёта в «Счетах» другой, это будет написано. Под полем видно, как программа поняла ввод. «Загрузить из manager» показывает: номер аккаунта и ссылки (Данные пользователя, Базовая анкета, Госуслуги), логин, (0.8.1) **e-mail аккаунта** - поле «E-mail» «Данных пользователя» (с логином может не совпадать; он же - в доменах), тип базовой анкеты (физлицо / ИП / юрлицо), **обслуживающую организацию** («текущая: ООО "РДХ"») и статус идентификации аккаунта через Госуслуги.

Базовая анкета читается со страницы «Данные пользователя» (`/manager/user_details?user_id=…`: блок, который открывает ссылка «Базовая анкета пользователя», есть на странице всегда, просто скрыт) и со страницы `/user/<номер>/runic_details` - та, что открывается по «Изменить базовую анкету». По логину/e-mail номер аккаунта находится через `/user/<логин>/runic_details`.

В таблице «Домены в manager» у номера аккаунта есть кнопка **«→ ЛК»** - открывает эту вкладку с этим аккаунтом.

**2. Текущий владелец: базовая анкета ↔ заявление.** Данные заявления пока вводятся вручную. Набор полей - по типу базовой анкеты аккаунта (выбирается сам при загрузке, можно переключить: физлицо / ИП / юрлицо):

- **физлицо** - фамилия, имя, отчество, дата рождения, гражданство (страна), серия и номер паспорта, дата выдачи, кем выдан, телефон;
- **ИП** (с 0.7.3) - то же плюс `ru_pp.code` ↔ ИНН ИП;
- **юрлицо** (с 0.7.3, группа `ru_org`):

| Базовая анкета | Заявление | Как сравнивается |
|---|---|---|
| `ru_org.org_r` | Название организации | организационно-правовая форма сокращением = полностью (ООО = «Общество с ограниченной ответственностью»), название должно совпасть |
| `ru_org.code` | ИНН организации | по цифрам |
| `ru_org.kpp` | КПП | по цифрам |
| `ru_org.address_r_addr` | Физический адрес | по названиям и номерам: «г.», «ул.», «д.», «дом», «улица» и порядок не важны; разные номера (дом, квартира, индекс) - красный; с одной стороны есть лишнее (индекс, область, офис) или адрес записан похоже - жёлтый |
| `ru_org.p_addr_addr` | Почтовый адрес | так же |
| `ru_org.phone` | Телефон | по цифрам; в анкете бывает несколько - достаточно совпадения с одним |
| `ru_org.e_mail` | e-mail | без учёта регистра |

Зелёный - совпадает, красный - расходится, жёлтый - похоже / написано по-разному, без цвета - сравнивать не с чем. Все поля базовой анкеты (в том числе не участвующие в сверке) - под спойлером «Все поля базовой анкеты».

**3. Новый владелец → базовая анкета.** Выберите, кто новый владелец (**физлицо / ИП / юрлицо**; после загрузки аккаунта выбран тип его анкеты), заполните форму (как в заявлении) и нажмите **«Заполнить автоматически»** - в любой момент. Программа найдёт открытую вкладку «Базовая анкета пользователя #…» этого аккаунта или откроет её сама, проверит, что в ней тот же номер аккаунта, и **заменит поля, которые заполнены в форме**. Если тип анкеты на странице другой (например, «Физик», а новый владелец - юрлицо), программа переключит его («Физик / ИП / Юрик») - страница сама покажет нужную форму. Пустые поля формы анкету не меняют. Заполненные поля обводятся, страница manager сама помечает их как изменённые и пересчитывает English name. **«Сохранить» в manager нажимаете вы.**

Физлицо:

| Поле в manager | Откуда |
|---|---|
| Фамилия, Имя, Отчество | из формы (ЗАГЛАВНЫЕ → «Сидорова») |
| Номер и серия | серия и номер; паспорт РФ - 10 цифр слитно, как в анкете |
| Дата выдачи, Кем выдан | из «Кем и когда выдан документ» (как в заявлении: дата и орган разделяются сами; код подразделения отбрасывается) или из отдельных полей |
| Дата рождения | ДД.ММ.ГГГГ |
| Город | из адреса регистрации («г. …», «город …», Москва / Санкт-Петербург / Севастополь, иначе посёлок/село/деревня); можно вписать самому |
| Почтовый адрес | адрес регистрации 1 в 1 |
| Получатель | Фамилия Имя Отчество (можно вписать самому) |
| Индекс | только если указан; пусто - остаётся прежний |
| Телефон | +7XXXXXXXXXX |
| Email | как есть (строчными) |

Не трогаются: **Гражданство** и **Страна почтового адреса** (выставляете сами), English name (пересчитывает страница), Область, Телефонный номер sms-безопасности, Факс, флажок «Внесены данные нового владельца аккаунта».

ИП (с 0.7.3) - всё, что у физлица, плюс:

| Поле в manager | Откуда |
|---|---|
| ИНН | ИНН ИП (12 цифр; другое число - с пометкой) |
| Адрес регистр., Город и Индекс адреса регистрации | адрес регистрации, город из него, индекс (пусто - остаётся прежний); почтовый адрес - тот же, 1 в 1 |

Юрлицо (с 0.7.3, форма «Юрик»):

| Поле в manager | Откуда |
|---|---|
| Название | название организации как в заявлении (English name пересчитывает страница) |
| ИНН, КПП | только цифры (ИНН - 10, КПП - 9; другое число - с пометкой) |
| Юр. адрес, его Город и Индекс | физический адрес из заявления; город - из адреса; индекс - если указан |

Не трогаются у юрлица: **Страна регистрации** и **Страна почтового адреса** (выставляете сами), English name, Область, Название родительской организации, Телефонный номер sms-безопасности, Факс, флажок «Внесены данные нового владельца аккаунта».

- **«Вернуть как было»** - вернуть в форме manager значения, которые были до заполнения, и прежний тип анкеты, если его переключали (пока «Сохранить» не нажато).

## 6. Вход в manager

Если manager показывает окно **«Войти»**, расширение:

1. выводит вкладку manager на передний план;
2. пишет в «Ходе работы»: *manager просит вход…*;
3. ждёт, пока вы войдёте (по умолчанию до 3 минут), и продолжает само.

Если окна «Войти» не видно, обновите вкладку manager (F5).

Если за отведённое время вход не выполнен, домен получает ошибку «Вход в manager не выполнен», остальные домены пропускаются. Войдите и нажмите «Загрузить данные из manager» ещё раз.

Проверить вход заранее: значок расширения → **«Проверить вход в manager»**.

## 7. Что делает расширение и что уходит наружу

- **Своя фоновая вкладка.** Расширение открывает вкладку `https://manager.reg.ru/` в фоне и загружает в ней страницы:
  - `/bill/bills?searchstring=<домен>&from_head=1&_csrf=<токен>`;
  - `/tech/srv_details?service_id=…`;
  - `/tech/service_details?service_id=…`;
  - (0.6.0) страница по ссылке «Идентификация через Госуслуги» со страницы Sd;
  - (0.6.0, вкладка «Смена владельца ЛК») `/manager/user_details?user_id=…` и `/user/<номер или логин>/runic_details`;
  - (0.7.6, рабочее место) `/manager/domain_move` - во вкладке, которую вы видите, и `https://www.gosuslugi.ru/621102/1/form`
    («Проверка действительности паспорта»);
  - (0.8.0, строка «Поиск») сайты, которые вы открываете сами: поисковики, egrul.nalog.ru, быстрые ссылки. На страницах
    `e-trust.gosuslugi.ru`, `crypto.kontur.ru` и `nextcloud-ms.runity.ru` работает скрипт приёма перетащенных файлов
    дела (`content/drop.js`); для этого у расширения есть доступ к этим сайтам и к программе на `127.0.0.1`.

  Это обычные GET-запросы - то же самое, что переход по ссылкам. Вкладка закрывается через 60 секунд без работы. Ту вкладку, которую вы сейчас смотрите, расширение не закрывает.
- **Файл данных ЕСИА** (0.6.0) лежит на `https://identity.reg.ru/esia/….json` (ссылка «Смотреть файл»). Расширение загружает его с вашим входом; если сразу не получилось - открывает ссылку в фоновой вкладке, читает и закрывает её. В программу из файла передаются только поля для сверки (ФИО, дата рождения, гражданство, серия, номер, дата выдачи, кем выдан) и признаки `trusted`, `vrf_stu`. ИНН, СНИЛС, адреса, телефон, e-mail, oid из файла не передаются. У файла организации (0.7.2) - название, ИНН, КПП, ОГРН, признак ликвидации, `trusted` и юридический адрес; ФИО представителя (`prs_auth_*`), телефон, e-mail, почтовый адрес и oid не передаются. Из Sd юрлица с 0.7.2 передаются ещё улица, дом, корпус, строение и индекс юридического адреса.
- **Кнопки manager не нажимаются.** «Сохранить», «Изменить», «Удалить», «Совершить массовое действие», «Актуализировать данные ЕСИА», «Аннулировать идентификацию» и другие формы manager расширение не трогает. Единственное изменение - значения полей формы на странице базовой анкеты (физлицо, с 0.7.3 - ИП и юрлицо) и, если новый владелец другого типа, переключатель «Физик / ИП / Юрик» - по кнопке «Заполнить автоматически», во вкладке, которую вы видите. Сохраняете вы.
- **В программу передаются только перечисленные выше поля.** С 0.5.0 к ним добавлен контактный e-mail администратора: `e_mail` (.RU/.РФ/.SU) и `o_email` (остальные зоны), а для остальных зон - название организации или ФИО владельца (`o_company`, `o_last_name`… группы `o_*`). Код передачи домена (`authinfo`), телефоны, адреса, `FOA_token` и служебные поля Sd не забираются. Во вкладке «Смена владельца ЛК» передаётся базовая анкета аккаунта целиком (в ней есть телефон, e-mail, почтовый адрес - они нужны для сверки и автозаполнения), логин, обслуживающая организация и статусы аккаунта. (0.8.4) Для MO - ещё почтовый адрес из Sd (`p_addr_*`), город и квартира юридического адреса и поля базовой анкеты владельца аккаунта, которые сверяются (ФИО, паспорт, ИНН/КПП, название, телефон, e-mail, индекс, город, адрес); SMS-номер, факс, English name, oid и остальное не передаются.
- **Связь только внутри компьютера.** Расширение связывается только с программой PySimpleManager на этом же компьютере (`ws://127.0.0.1:8765/ext`). Программа принимает подключения только от расширений Chrome, обычные сайты подключиться не могут.
- **WHOIS - единственный запрос наружу.** Только для доменов, которых нет в manager, и в нём уходит только имя домена:
  - .RU / .SU / .РФ → `whois.tcinet.ru:43`;
  - другие зоны → WHOIS их реестра или `rdap.org`.

Проверить WHOIS из командной строки: `py -3.12 -m doctool whois example.ru`.

| «Аккаунт #… оформлен на …: автозаполнение без типа нового владельца - только для физлиц» | Расширение обновлено до 0.7.3, а программа старая (или наоборот). Обновите обе и перезапустите `doctool_web.bat`. |
| «Не удалось переключить базовую анкету на «Юрик»…» | Страница manager не показала нужную форму. Переключите тип вручную, обновите вкладку (F5) и нажмите «Заполнить автоматически» ещё раз. |
| «Во вкладке базовая анкета аккаунта #X, а нужен #Y» | Закройте лишнюю вкладку базовой анкеты или загрузите в программе нужный аккаунт. |
| «ЕСИА: ошибка: Файл ЕСИА не открылся…» | Откройте ссылку «JSON-файл» в окне ESIA: если файл просит вход - войдите и загрузите домены ещё раз. Проверьте, что в `chrome://extensions` у расширения есть доступ к identity.reg.ru. |
| Chrome при запуске предлагает отключить расширения в режиме разработчика | Нажмите «Отмена». Если режим разработчика запрещён политикой компании - нужен администратор, чтобы установить расширение централизованно. |

## 10. Ограничения

- **Поиск в счетах - по первой странице выдачи** (25 позиций). Для доменов с очень длинной историей счетов строка домена может не попасть на первую страницу.
- **Типы контактов:** `ru_pp` и `ru_org` сверяются с документами. Остальные (группы `o_*` других зон) - показываются администратор и e-mail, сверка - вручную.
- **Домен на юрлицо** со сверкой бланка физлица - всегда ручная проверка.
- **Автозаполнение** - базовая анкета (вкладка «Смена владельца ЛК»): физлица, с 0.7.3 - ИП и юрлица; с 0.7.6 - «Перенос доменов между аккаунтами» (шаги 1–2) и форма проверки паспорта на Госуслугах (раздел 5а). Данные заявления для смены владельца пока вводятся вручную (шаблоны заявлений - позже). Формы ИП и юрлица проверены на обезличенных копиях страниц manager; на реальной странице переключение типа и заполнение стоит один раз проверить глазами перед «Сохранить».
- **ЕСИА** - для доменов физлиц и юрлиц (.RU/.РФ/.SU); у остальных зон нет; на вердикт не влияет.
