# Changelog — PySimpleManager (до 0.7.1 — doctool)

Изменения по версиям, сверху — новые. Changelog ведётся с версии 0.2.2 (05.10.2026). Записи для 0.1–0.2.1 восстановлены по истории проекта (`claude/context/environment-and-history.md`), поэтому они менее подробны.

Как ведётся:

- Каждая версия — отдельный раздел. Внутри — «Добавлено», «Изменено», «Исправлено», «Удалено». Отдельно — «Совместимость», если меняются конфиги, формат выгрузки или поведение вердикта.
- Версия хранится в `doctool/__init__.py`. Начиная с 0.2.2 изменения патч-версии не меняют прежние вердикты на «Принять» без оснований: любое ослабление проверок отмечено в «Совместимости».
- diff с предыдущей версией (`doctool-gui-<было>-to-<стало>.diff`) кладётся рядом с архивом `doctool-X.Y.Z.zip`; в проекте Claude diff не хранится (с 14.10.2026). Любую версию можно взять из git-репозитория по тегу или из архива. Актуальный код — `claude/code/doctool-gui/…` (имя дерева историческое: окна Qt в программе больше нет).

## [0.8.1] — 2026-10-15

Запрос пользователя 14.10.2026: окна рабочего места без заявления; копировать текст PDF, как в браузере; убрать окно
сверки и «Новую проверку»; e-mail аккаунта — из поля «E-mail»; без Яндекса.

### Добавлено
- Рабочее место **без файлов** (кнопка на приёме) и **файлы в открытое дело**: перетащить архив/файлы на рабочее место
  или «Добавить файлы» — разбираются только новые страницы, проверка запускается заново (`POST /api/ws` без файлов,
  `POST /api/ws/{id}/files`, `WorkspaceManager.add`).
- **Текст страниц PDF выделяется и копируется** в окнах документов и в откреплённом окне: прозрачный слой слов поверх
  превью с учётом масштаба и поворота (`GET /api/ws/{id}/text/{pid}`, `Workspace.text_layer`). У сканов текста нет.
- **E-mail аккаунта** — поле «E-mail» страницы «Данные пользователя» (с логином может не совпадать): расширение читает
  его при загрузке доменов (раз на аккаунт) и в «Смене владельца ЛК»; показывается рядом с логином в «Доменах», Sd,
  таблице и выгрузке по доменам, отчёте (`account_email`, `email`).

### Удалено
- Окно **«Сверка»** (Sd / ЕСИА / заявление / паспорт) вместе с блоком «Паспорт на Госуслугах» и отметками
  «Действителен / Недействителен»; подсветка мест полей. «Открыть смену в manager» требует только: нет «стопа», есть
  домены, вердикт не «Отклонить». «Госуслуги · паспорт» в строке «Поиск» осталась (только вписывает): серия, номер и
  ФИО — из строки запроса («4012 654321 Иванова Анна»), иначе из паспорта дела, иначе из Sd домена.
- Во вкладке «Проверка заявления и домены» — «Новая проверка», ход работы и результат (в т. ч. ручной ввод заявления);
  вкладка называется **«Домены в manager»**. API `/api/jobs*` остались (рабочее место, командная строка, тесты).
- **Яндекс** в строке «Поиск» (Shift+Enter — ЕГРЮЛ).

### Совместимость
- Расширение 0.8.1 (`content/manager.js`): без обновления e-mail аккаунта не приходит, остальное работает.
- Свой `config/workspace.yaml` с Яндексом продолжит его показывать — уберите строку `yandex` из `search.services`.
- Раскладки окон: «Сверки» нет, сохранённая «Моя» применяется к остальным окнам.

## [0.8.0] — 2026-10-14

Задача: проверки в браузере — паспорт, ЕГРЮЛ, поиск, проверка подписи, Nextcloud — не переключаясь с рабочего места
(запрос пользователя 14.10.2026: «поисковое окошко браузера внутри вкладки рабочее место… вызвать по кнопке и
убрать»; «чтобы всё было перед глазами… на отдельную вкладку переключаться не хочется»). Встроить сайты в страницу
программы нельзя: они запрещают показывать себя внутри чужих страниц (у Google — `X-Frame-Options: SAMEORIGIN`), а вход
на Госуслуги в таком окне не сохраняется. Поэтому сайт открывается **рядом** с рабочим местом — во второй половине
окна Chrome (разделённый экран, Split View; Chrome 145+, расширениям — с Chrome 155) или отдельным окном справа.
Предложение, варианты показа, макет и решения — `claude/context/v0.8.0-search-panel.md`.

### Добавлено

- **Строка «Поиск»** в рабочем месте (кнопка «Поиск» на панели над окнами или **Ctrl+K**; та же кнопка, Ctrl+K, Esc
  или × — убрать):
  - поле запроса; под ним при вводе — значения дела одним щелчком (ФИО из паспорта, Sd и заявления, серия и номер,
    дата рождения, ИНН, домены, ФИО и паспорт из Sd, организация и ИНН юрлица, новый администратор, договор;
    Shift+щелчок — добавить к запросу) и запросы этого дела (сохраняются в деле, щелчок — открыть снова);
  - сервисы: **Google** (Enter), **Яндекс** (Shift+Enter), **ЕГРЮЛ** — расширение открывает egrul.nalog.ru и вписывает
    запрос в поле поиска («Найти» нажимает оператор), **Госуслуги · паспорт** — то же, что «Вписать на Госуслугах»;
  - быстрые ссылки: **Nextcloud** (`nextcloud-ms.runity.ru`), **Проверка ЭП · Госуслуги** (`e-trust.gosuslugi.ru`),
    **Контур.Крипто** (`crypto.kontur.ru/decrypt`);
  - где открывается сайт (выбор в строке, запоминается в браузере): «рядом (авто)» — во второй половине окна Chrome
    рядом со вкладкой программы, если не получается — окном справа; «вторая половина Chrome»; «окном справа» —
    отдельное окно Chrome на правой части экрана, окно программы сдвигается влево; «вкладкой». Следующий запрос
    открывается там же — вкладки не копятся. «Убрать» — вкладка сайта выходит из разделённого экрана и остаётся
    (окно справа сворачивается, окно программы возвращается на место); «Поиск» снова — сайт на месте, без
    перезагрузки. В Chrome 145–154 пару вкладок можно собрать вручную (правый щелчок по вкладке программы) —
    расширение откроет сайт во второй вкладке пары;
  - строка состояния: что открыто и где, что вписано и что нажать; у Госуслуг — «Действителен / Недействителен»
    (отметка в деле и в «Сверке»); «?» — как это устроено, версия Chrome и есть ли у расширения разделённый экран;
  - без расширения сайт открывается обычным окном браузера справа, запрос для ЕГРЮЛ копируется в буфер обмена.
- **Файлы дела — на страницу сайта перетаскиванием**: из строки «Файлы:» в строке поиска, из ленты страниц
  (миниатюра — файл этой страницы) и из списка «Подпись и другие файлы» — на страницу проверки ЭП, Контур.Крипто или
  Nextcloud. Со страницы программы уходит только ссылка на файл; расширение (`content/drop.js`) берёт файл у
  программы и кладёт его на страницу событием «перетащили из папки», а если страница его не приняла — в поле выбора
  файла. Принимаются только файлы дел PySimpleManager и только настоящее перетаскивание мышью. Файл можно перетащить
  и в папку Windows (`DownloadURL` — возможность Chrome; не проверялось).
- **Меню «Окна»** на панели над окнами: все окна рабочего места с состоянием (открыто, свёрнуто, закрыто,
  откреплено) — щелчок открывает любое, в том числе Sd каждого найденного домена и окно manager (через те же
  «ворота», что и кнопка «Открыть смену в manager»); **«Показать все»** — вернуть свёрнутые окна на их места без
  раскладки (окно заявления не сдвигается); «Sd всех доменов»; показать / убрать строку «Поиск».
- **Окно «Домены»**: у физлица — серия и номер паспорта, дата выдачи и «кем выдан» из Sd (как в «Домены в manager»),
  у юрлица — ИНН; «в поиск» — вписать в строку «Поиск».
- **Удаление недавних дел**: на экране приёма у каждого дела «Удалить» (подтверждение в строке) и «Удалить все (N)»
  (подтверждение над списком). С диска стираются папка дела `results/_workspace/<время>_<id>` и папки результатов его
  проверок (`results/<время>_<дело>`, запоминаются в `ws.json` → `result_dirs`). Удаляется только то, что лежит
  внутри папки результатов программы; папки других дел не трогаются; дело, которое ещё разбирается, не удаляется.
  API: `DELETE /api/ws/{id}`, `POST /api/ws/recent/clear`; `/api/ws/recent` отдаёт `total`.
- **`config/workspace.yaml`, раздел `search`**: `open_in` (auto / split / window / tab), `window_share` (ширина окна
  справа, 20–70 % экрана), `services` (кнопки: `title`, `url` с `{q}`, `fill: egrul` — вписать запрос в форму) и
  `links` (быстрые ссылки). `validate` проверяет раздел. `/api/ws/meta` отдаёт `search`.
- **API сайта рядом**: `POST /api/site/open` (`url`, `fill`, `q`, `open_in`, `screen` — область экрана браузера,
  `keep` — показать снова без перезагрузки), `POST /api/site/hide` (`close` — закрыть). `/api/ws/{id}/gosuslugi`
  принимает `site` — где открыть страницу. `/api/manager/status` — версия Chrome и есть ли у расширения разделённый
  экран (`chrome`, `split_api`).
- **Расширение 0.8.0**: команды `site_open` (разделённый экран — `tabs.create({splitWithTabId})`, снова собрать пару —
  `tabs.createSplit`, пара, собранная вручную, — `Tab.splitViewId`; окно справа — `windows.create` типа popup и
  сдвиг окна программы; вкладка; `fill` — вписать запрос в поле поиска), `site_hide` (`tabs.unsplit` / свернуть окно и
  вернуть окно программы на место); `gosuslugi_fill` открывает страницу там же. `site_open`, `site_hide` и
  `gosuslugi_fill` выполняются сразу, не дожидаясь очереди загрузки доменов из manager. В `hello` — версия Chrome и
  наличие API разделённого экрана. `content/drop.js` — приём перетащенных файлов дела на e-trust.gosuslugi.ru,
  crypto.kontur.ru, nextcloud-ms.runity.ru. Новые сайты в `host_permissions`: egrul.nalog.ru, e-trust.gosuslugi.ru,
  crypto.kontur.ru, nextcloud-ms.runity.ru и программа на `http://127.0.0.1` / `http://localhost` (взять файл дела).
- Тесты: `tests/test_workspace_search.py` (настройки `search`, API сайта рядом с подменой расширения, Госуслуги с
  `site`, история запросов в деле, безопасное удаление дел), `test_workspace.py` — удаление дела вместе с результатом
  проверки. Проверка интерфейса в Chromium — `claude/tools/e2e_workspace/run_ui_080.py` (42 проверки); расширения в
  Chrome for Testing 155 (окно под Xvfb, имитация сайтов) — `claude/tools/e2e_extension/run_ext_080.py`
  (21 проверка, в том числе настоящее перетаскивание мышью из рабочего места на сайт во второй половине окна) и в
  Chromium 141 — запасной путь окном справа (5).

### Изменено

- «Вписать на Госуслугах» (окно «Сверка») открывает страницу проверки паспорта там же, где сайты строки «Поиск»;
  уже открытая форма не перезагружается.
- Миниатюры ленты и файлы в «Подпись и другие файлы» можно перетаскивать на сайт (перенос миниатюры в группу или в
  окно документа работает как раньше).
- Окно расширения (popup) — описание того, что оно делает, с учётом сайтов рядом.

### Совместимость

- Расширение нужно обновить (chrome://extensions → «Обновить»): Chrome может попросить подтвердить доступ к новым
  сайтам. Со старым расширением строка «Поиск» открывает сайты обычным окном браузера (без вписывания в ЕГРЮЛ и без
  перетаскивания файлов), «Вписать на Госуслугах» работает как в 0.7.6.
- Разделённый экран расширение собирает само только в Chrome 155+; в Chrome 145–154 — если пару вкладок собрали
  вручную; иначе сайт открывается окном справа.
- Адрес Nextcloud (`nextcloud-ms.runity.ru`) теперь есть в `config/workspace.yaml` и `manifest.json` — в публичном
  репозитории. Если это нежелательно — свой `workspace.yaml` в папке данных и правка `manifest.json` у себя.
- Вердикт, проверки, `export.json`, `case_types.yaml` не менялись. `ws.json` — новые ключи `result_dirs` и
  `state.search` (старые дела открываются как раньше).
- Не проверено на живых сайтах (облако до них не достаёт — проверено на имитации): поле поиска egrul.nalog.ru
  (ищется `#query`, иначе первое видимое текстовое поле), приём файлов на e-trust.gosuslugi.ru, crypto.kontur.ru и
  в Nextcloud (у каждого своя зона загрузки; на странице dashboard Nextcloud загрузки нет — откройте папку «Файлы»),
  разделённый экран и перетаскивание на Windows (проверено в Chrome 155 для Linux).

## [0.7.6] — 2026-10-14

Задача: одно рабочее место для заявления на смену администратора — все документы видны сразу в нескольких окнах,
сверка Sd / ЕСИА / заявление / паспорт рядом, проверка паспорта на Госуслугах и смена администратора в manager по
кнопке (расширение заполняет страницы, но ничего не отправляет), готовая строка для таблицы xlsx. Нейросеть не
используется: страницы разбираются по тексту, ключевым словам и строкам MRZ (решения пользователя 12–14.10.2026,
`claude/context/proposal-2026-10-13-operator-workspace.md`).

### Добавлено

- **Вкладка «Рабочее место»** (первая, открывается по умолчанию; дальше — последняя открытая вкладка;
  `doctool/static/workspace.js`, `workspace.css`, сервер — `doctool/workspace.py`, API `/api/ws/*`):
  - **Приём дела**: архив из тикетницы (zip, rar, 7z — в том числе архив в архиве) или сами файлы перетаскиваются
    в окно; номер тикета (кнопка «Вставить» — из буфера; номер без «#» дополняется им в строке таблицы), тип
    операции, способ получения. «Недавние дела» — открыть снова (всё состояние дела хранится в
    `results/_workspace/<время>_<id>/ws.json`).
  - **Лента страниц**: каждая страница PDF, изображение (многостраничный TIFF — по кадрам), DOCX (и фото,
    вставленные в Word) — миниатюра в группе «Заявление», «Паспорт», «Прочее», «Не определено», «Скрытые» (пустые
    страницы и повторы — по «отпечатку» изображения). Разбор без нейросети: текстовый слой PDF или быстрый OCR,
    заголовок бланка (модули заявлений), слова паспорта и прописки, строки MRZ, поворот страницы (подсказка Tesseract
    OSD, затем угол, при котором OCR находит больше слов). Уверенность и причина — в подсказке миниатюры. Подписи `.sig/.p7s` — отдельным списком (только ссылка:
    проверяются вручную), неподдерживаемые файлы — с пометкой.
  - Перенос страницы в другую группу — перетаскиванием миниатюры (в группу или в окно документа), поворот — ↻,
    **«⬚ Рамкой → паспорт»** — вырезка паспорта со страницы заявления (заявление и паспорт в одном файле, фото
    паспорта на странице бланка). После правок — «Перепроверить»: проверка по новым страницам.
  - **Окна** — заявление, паспорт, сверка, домены, строка таблицы (и по кнопкам — Sd домена, manager, отдельные
    страницы): перетаскивание за заголовок, размер — за любой край и угол, прилипание к краям и к соседним окнам,
    к краю экрана — половина / четверть, к верху — во весь экран; свернуть (док внизу панели), развернуть
    (двойной щелчок по заголовку). Раскладки: «3 колонки», «Документы крупно», «Сетка 2×2», «Каскад», «Моя»
    («Запомнить мою» — своя для каждого типа операции). «Разложить» — каждая страница документа в своём окне;
    «Открепить» — документ в отдельном окне браузера (на второй монитор).
  - Просмотр страницы: масштаб (кнопки, Ctrl + колесо — к курсору), «по ширине», перетаскивание мышью; DOCX —
    текстом.
  - **Сверка** — строки ФИО, дата рождения, серия и номер, дата выдачи, кем выдан, код подразделения, …: значения
    Sd (домен — выбор, если доменов несколько), ЕСИА, заявления, паспорта рядом, с цветом совпадения; пустые
    колонки (нет ЕСИА, паспорт не прочитан) скрываются. Выбор строки подсвечивает место поля на странице заявления
    (скан — по координатам распознавания, PDF и DOCX — по тексту) и прокручивает к нему. ✓ / Enter — совпадает,
    ✗ / Пробел — расхождение с примечанием, ✎ — исправить значение заявления (проверки пересчитываются), ↑↓ —
    по строкам; строки, где всё совпало само, отмечены «совпадает».
  - **Паспорт на Госуслугах**: «Вписать на Госуслугах» — расширение открывает «Проверка действительности паспорта»
    и вписывает серию, номер, фамилию и имя; «Продолжить» оператор нажимает сам; результат — кнопками
    «Действителен» / «Недействителен».
  - **Домены**: карточки доменов из manager (Sd, S, ЕСИА) — администратор, ЕСИА, последняя смена администратора,
    provider, аккаунт и **его логин**, буква **«К»** при комментарии администратора в S (окошко с текстом и
    «Копировать»), проверки домена; галка — домен участвует в смене и в строке таблицы. Список доменов можно
    поправить и загрузить заново («Загрузить из manager»). Окно Sd — поля Sd и S рядом со сверкой.

- **Проверка «Кем выдан ↔ данные системы».** Работает, если в данных администратора заполнено `passport_issued_by` и в системе тот же паспорт.
- **`AdminData.passport_issued_by`.** Поле «Кем выдан» добавлено в данные администратора в окне Qt и веб-интерфейсе. В `export.json` → `system_update` появилось `passport_issued_by` («было → станет»).
- **Причины ручной проверки в `config/case_types.yaml` (тип `passport_only`)** — отдельно по сроку действия, «кем выдан», региону и данным системы.
- **Тесты.** Их 17 (+6): регионы, исправление OCR, допуск по серии, `passport_only` (принять / ручная проверка / без даты выдачи).
- **Тестовый образец** `Dataset\set7\PassportSet7.png` (Опря).

### Изменено

- **`passport_rf._merge_lines`.** Строка из нескольких проходов OCR выбирается по согласию проходов, а не по максимуму «уверенность × длина». Для «кем выдан» приоритет получают слова названий органов («ОБЛАСТИ», а не «ВЛАСТИ»).
- **«Кем выдан» из OCR.** Явные опечатки правятся: «РООСИИ» → «РОССИИ», «МОСКОВСКОЙ ВЛАСТИ» → «… ОБЛАСТИ». Исходное прочтение сохраняется в `alternatives` и `raw`, список правок — в `debug.issued_by_fixes`.
- **Проверка «Серия ↔ год выдачи».** Если год бланка по серии опережает год выдачи на 1 год, это «к сведению» (бланки печатают с опережением). На 2–3 года → «проверить». Больше 3 лет → «так не бывает».
- **Строки таблицы GUI.** «Кем выдан» и «Код подразделения» теперь показывают статус новых проверок.

### Исправлено

- **`passport_rf.plausibility`.** Дата выдачи из MRZ отбрасывалась, если год выдачи меньше года бланка по серии (серия 46 19, выдан 17.10.2018). Теперь:
  - значения из MRZ и введённые оператором не отбрасываются никогда;
  - для остальных значений допуск по серии — 3 года (`SERIES_YEAR_LEAD`);
  - у даты в будущем — правильное сообщение.
- **Пропуск проверки срока действия.** «Срок действия паспорта» молча пропускалась, если дата выдачи или рождения не распознана. Теперь это «нужна ручная проверка». Из-за этого `passport_only` давал «Принять» на почти не распознанном паспорте (набор 2 без модели).
- **«Кем выдан» в `passport_only`.** Проверка отфильтровывалась (её не было в списке `keep` в `service._evaluate`).

### Совместимость

- **Вердикты стали строже.** Если паспорт без распознанной даты выдачи раньше давал «Принять», теперь он даёт «Ручная проверка». Ослаблена только проверка «Серия ↔ год выдачи»: опережение на 1 год больше не даёт «проверить».
- **Старые JSON с данными администратора** работают: новое поле `passport_issued_by` необязательно.
- **Регрессия:**
  - Попова → «Принять»;
  - Семичев → «Ручная проверка»;
  - Аверин без модели → «Ручная проверка»;
  - Опря (`passport_only`) → «Принять»;
  - Рудаков (`passport_only`, без модели) → «Ручная проверка» (было «Принять»).

### Известные ограничения

- Допуск «опережение серии до 3 лет» нужно сверить с регламентом. На образце подтверждено только опережение на 1 год.
- Третья цифра кода подразделения и регион серии (ОКАТО) не проверяются.
- В месте рождения на образце 7 остаётся мусорный хвост из водяных знаков.
