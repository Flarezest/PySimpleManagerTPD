# PySimpleManager: локальная проверка заявлений и паспортов РФ

> С версии 0.7.1 программа называется **PySimpleManager** (раньше — doctool). Внутренние имена не менялись: пакет и команды `python -m doctool …`, файл `doctool_web.bat`, папка расширения `doctool_extension`, схема выгрузки `doctool.case.v1`.

Инструмент извлекает данные из заявления (PDF с текстовым слоем, DOCX, скан или фото) и из паспорта РФ (скан или фото), сверяет их между собой, выполняет формальные проверки и выносит вердикт: **принять / отклонить / ручная проверка**. Правила вердикта задаются в конфиге отдельно для каждого типа заявления.

Результат:

- HTML-отчёт с фрагментами для ручной проверки;
- выгрузка «актуальных данных» в JSON — для будущего автозаполнения во внутренней системе;
- общий Excel-реестр проверок.

Работать можно в **браузере** (локальный веб-интерфейс) или из **командной строки**. Окна приложения (Qt) с 0.7.4 нет.

С версии 0.3.0 веб-интерфейс умеет сам загружать данные доменов из **manager** (Sd — администратор, S — `provider` и аккаунт) через расширение Chrome «PySimpleManager» и сверять их с паспортом и заявлением. Установка и работа — **[docs/MANAGER.md](docs/MANAGER.md)**. Домены в таблице выводятся по «проблемности»: сначала свободные по WHOIS, затем те, у которых данные в Sd не сходятся с документами, ниже — остальные (с 0.4.0). С 0.5.0 — e-mail администратора из Sd и кнопка «Выгрузка по доменам (HTML)». С 0.6.0 — статус идентификации администратора домена через Госуслуги (ЕСИА) и окно сверки Sd ↔ ЕСИА (кнопка ESIA), а также вкладка **«Смена владельца ЛК»**: базовая анкета аккаунта, сверка с заявлением и автозаполнение анкеты данными нового владельца (сохраняет оператор). С 0.7.2 — ЕСИА и у доменов юрлиц (ИНН, КПП, название, юридический адрес), в выгрузке по доменам `provider` — отдельная колонка с сортировкой. С 0.7.3 — ручной ввод данных заявления со сверкой с manager (домены после «Пересчитать» уходят на поиск сами), сверка и автозаполнение базовой анкеты для ИП и юрлиц. С 0.7.6 — вкладка **«Рабочее место»**: архив из тикетницы (zip, rar, 7z) раскладывается по страницам заявления и паспорта, все документы видны сразу в перетаскиваемых окнах, сверка Sd / ЕСИА / заявление / паспорт рядом с подсветкой мест полей на странице, проверка паспорта на Госуслугах и смена администратора в manager по кнопке (расширение заполняет страницы, отправляет оператор), буква «К» — комментарий администратора в S, готовая строка для таблицы xlsx (все поля правятся) — [docs/USAGE.md, раздел 2.7](docs/USAGE.md). С 0.8.0 — строка **«Поиск»** (Ctrl+K): Google, ЕГРЮЛ, Госуслуги и быстрые ссылки (Nextcloud, проверка ЭП, Контур.Крипто) открываются рядом с рабочим местом — во второй половине окна Chrome (разделённый экран) или окном справа; файлы дела перетаскиваются на страницу сайта; меню «Окна»; паспорт в окне «Домены»; удаление недавних дел. С 0.8.1 — рабочее место без файлов (файлы — потом, перетаскиванием), выделение и копирование текста PDF, вкладка «Домены в manager» вместо «Проверка заявления и домены», без окна «Сверка», e-mail аккаунта из поля «E-mail». С 0.8.2 — тип операции «Безбумажные операции» и кнопка с автозаполнением доверенности в manager; «Смена админа через manager» — при любой операции, без причины при пустом списке доменов. С 0.8.3 — верхнюю панель рабочего места можно убрать наверх (больше места для документов) и вернуть.

**Всё работает локально, документы никуда не отправляются.** Единственный запрос наружу — WHOIS по имени домена, которого нет в manager.

## Что проверяется

| Проверка | Как |
|---|---|
| ФИО в шапке, в «Я, …», у подписи ↔ паспорт | с учётом падежей (pymorphy3) и инициалов |
| Дата рождения, серия/номер, дата выдачи | точное совпадение; для серии/номера учитываются все варианты прочтения |
| Кем выдан | нечётко, с раскрытием сокращений (ОВД, ОУФМС, г., обл., р-на …) |
| Кем выдан (только паспорт) | надёжность прочтения + регион органа ↔ код подразделения (500-050 → Московская обл.); с данными системы — сверка с ними |
| Серия ↔ год выдачи | 3–4-я цифры серии — год изготовления бланка; опережение на 1 год — норма |
| MRZ | контрольные цифры (если зона есть, примерно с 2011 г.) |
| ИНН ИП | контрольные разряды |
| Указан прежний паспорт | номер из заявления найден в «ранее выданных паспортах» или ФИО совпадает, а паспорт старше предъявленного |
| Паспорт приложен | без паспорта заявление не принимается автоматически — «Ручная проверка» |
| Администратор доменов в manager (Sd) | ФИО и дата рождения из Sd ↔ паспорт; паспорт в Sd; домен на юрлицо; один ли администратор у всех доменов; e-mail администратора; домен не найден → WHOIS; выгрузка по доменам в HTML; ЕСИА: state и Sd ↔ данные Госуслуг (docs/MANAGER.md) |
| Смена владельца ЛК (физлицо, ИП, юрлицо) | базовая анкета аккаунта ↔ заявление (ввод вручную); автозаполнение базовой анкеты данными нового владельца (docs/MANAGER.md, раздел 5) |
| Домен | формат + punycode для .рф. Имя, перенесённое на следующую строку после дефиса (`business-⏎dvd.ru`), склеивается; число доменов сверяется с «всего N доменов» из заявления; обрывки имён без зоны → ручная проверка |
| Новый администратор, контакты, договор, дата заявления | заполненность; дата прописью разбирается в дату |

Адрес регистрации пока не сверяется: он стоит в штампе на страницах прописки и требует отдельного модуля.

## Установка установщиком (с 0.7.5) — для работы

Готовые установщики — на странице **Releases** репозитория (собирает GitHub Actions, как — [docs/RELEASE.md](docs/RELEASE.md)):

- **Windows 10/11** — `PySimpleManager-<версия>-windows-x64-setup.exe`: запустить и нажать «Установить». Права
  администратора не нужны, Python и Tesseract с русским языком уже внутри. Если Windows покажет «Система Windows
  защитила ваш компьютер» — «Подробнее» → «Выполнить в любом случае» (установщик не подписан сертификатом).
- **Linux** (Ubuntu 22.04+, Debian 12) — `sudo apt install ./pysimplemanager_<версия>_amd64.deb`.
- **macOS** (Apple Silicon, пробная сборка) — `.dmg`: папку `PySimpleManager` перетащить в «Программы», запускать
  `Запустить PySimpleManager.command`.

Запуск — ярлык «PySimpleManager»: откроется браузер, окно консоли остаётся, пока программа работает (закрыли окно —
программа остановилась). Результаты, реестр и свои настройки — в папке **«Документы\PySimpleManager»**, обновление
и удаление программы её не трогают. Обновление — новый установщик поверх старого. Расширение Chrome ставится один
раз вручную из папки `chrome_extension` программы (Пуск → PySimpleManager → «Расширение Chrome (папка)»;
[docs/MANAGER.md](docs/MANAGER.md), раздел 1).

## Установка из исходников (Windows) — для разработки

1. **Python 3.10–3.13** (рекомендуется 3.12) с https://www.python.org. Старый Python можно не удалять — новый ставится рядом, запуск через `py -3.12`.
2. **Tesseract OCR** — отдельная программа (pip её не ставит): установщик `tesseract-ocr-w64-setup-5.x.exe` от UB Mannheim (https://github.com/UB-Mannheim/tesseract/wiki).
   - На шаге компонентов раскройте *Additional language data (download)* и отметьте **Russian**.
   - Проверка в новом окне командной строки: `tesseract --list-langs` — в списке должны быть `eng`, `osd`, `rus`.
   - Если `rus` нет (установщик качает языки из интернета и мог не скачать): возьмите `rus.traineddata` из https://github.com/tesseract-ocr/tessdata и положите в `C:\Program Files\Tesseract-OCR\tessdata`.
   - PySimpleManager сам ищет Tesseract в PATH и стандартных папках; если поставили в другое место — `set TESSERACT_CMD=D:\путь\tesseract.exe`.
3. Отдельное окружение и зависимости (в папке проекта):
   ```
   py -3.12 -m venv .venv
   .venv\Scripts\activate
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   pip install -r requirements-web.txt
   ```
   Последняя строка нужна для веб-интерфейса. В следующий раз достаточно `.venv\Scripts\activate` перед запуском, а `.bat`-файлы активируют окружение сами.
4. *(Необязательно, нужно для рукописных заявлений)* **Ollama** (https://ollama.com) и модель:
   ```
   ollama pull qwen3-vl:4b-instruct
   ```
   Модели нужно около 3,5 ГБ памяти. С видеокартой NVIDIA одно поле распознаётся за 1–3 с. На CPU уходит от десятков секунд до пары минут на поле.

Linux: `apt install tesseract-ocr tesseract-ocr-rus`, затем те же шаги 3–4.

При запуске из исходников всё как раньше: `results/` — в папке программы, бланки и правила — `forms/`, `config/`. Чтобы работать с папкой данных, как установленная программа, задайте `DOCTOOL_HOME` (docs/USAGE.md, раздел 9).

## Использование

Полное руководство — интерфейсы, флаги, правила вердикта, формат выгрузки, параметры командной строки, типичные ошибки: **[docs/USAGE.md](docs/USAGE.md)**.

| Что | Как запустить |
|---|---|
| Веб-интерфейс | ярлык «PySimpleManager» (установленная программа), `doctool_web.bat` или `python -m doctool web` → http://127.0.0.1:8765 |
| Рабочее место (0.7.6): архив тикета → окна документов, сверка, Госуслуги, manager, строка таблицы | вкладка «Рабочее место» веб-интерфейса; настройки — `config/workspace.yaml` |
| (0.8.0) Строка «Поиск»: сайты проверок рядом с рабочим местом, файлы дела на сайт, меню «Окна», удаление дел | кнопка «Поиск» / Ctrl+K в рабочем месте; сервисы и ссылки — `config/workspace.yaml`, раздел `search` |
| Проверка из консоли | `python -m doctool check -a заявление.pdf -p паспорт.pdf` |
| Рукописное заявление | `python -m doctool --vlm qwen3-vl:4b-instruct check -a заявление.jpg --handwritten -p паспорт.pdf` |
| Поля заявления нейросетью (0.7.0) | галка «Поля заявления — нейросетью» или `python -m doctool --llm-fields qwen3:8b check -a заявление.pdf` |
| Всё в одном файле | `python -m doctool check -a комплект.pdf --combined` |
| Пакетно | `check_all.bat` (поправьте в нём путь к папке с делами) |
| Проверить описания бланков и типов заявлений | `python -m doctool validate` (`--list` — проверки, роли полей, типы) |
| Данные доменов из manager | веб-интерфейс + расширение Chrome из папки `doctool_extension` — см. [docs/MANAGER.md](docs/MANAGER.md) |
| WHOIS домена | `python -m doctool whois example.ru` |
| То же в установленной программе | `PySimpleManager.exe check …`, `… validate` (Windows, папка программы); `pysimplemanager …` (Linux) |
| Собрать установщик | тег `vX.Y.Z` → GitHub Actions; у себя — `python installer/build.py` ([docs/RELEASE.md](docs/RELEASE.md)) |

Каждая проверка создаёт папку `results/<дата_время>_<дело>/`:

- `report.html` — отчёт;
- `export.json` — выгрузка для системы;
- `result.json` — всё распознанное;
- `crops/` — фрагменты.

Все проверки собираются в `results/реестр_проверок.xlsx`.

### Как добавить новое заявление (модуль заявления, с 0.7.3)

Каждое заявление — отдельный модуль: папка `forms/<id>/`. Код ядра менять не нужно, если новому заявлению хватает
существующих проверок; особая логика бланка, если она нужна, живёт в его модуле.

1. **Папка модуля.** Скопируйте `forms/regru_transfer_person/` в `forms/<новый id>/` (hooks.py удалите, если особой
   логики нет) и поменяйте `form.yaml`:
   - `id` и `detect.keywords` — фразы, по которым заявление узнаётся; `detect.title` — заголовок бланка;
   - для каждого поля `type` — как разбирать значение (`fio`, `passport`, `domains`, `contact`… — список в шапке YAML)
     и `role` — смысл поля для проверок, если имя поля другое (например, `owner_fio` с `role: applicant_fio`
     сверяется с паспортом как «ФИО в тексте»). Роли — `python -m doctool validate --list`;
   - **`reference:` — как читать эталон** (PDF из Word, DOCX по бланку), без регулярных выражений: для каждого поля —
     печатная подпись после значения (`before`) и, если нужно, текст перед ним (`after`), обычными строками, в
     порядке бланка (подробно — шапка `form.yaml` и `doctool/reference.py`). Положите пустой бланк рядом как
     `blank.docx` — `validate` проверит, что все подписи в нём находятся по порядку;
   - `text` — регулярные выражения (группа 1 — значение) для того, что не похоже на бланк: свободная форма, бланк
     нотариуса, изменённая вёрстка, текст скана. Если заявления приходят только по бланку, их можно не писать;
   - `scan.anchor` / `scan.region` — где значение на скане (подпись поля и прямоугольник относительно неё),
     `scan.block_start` — абзац со списком доменов;
   - `labels_re`, `strip_prefixes`, `static_text` — печатный текст бланка, который вырезается из значений;
   - `rows` — свои строки таблицы интерфейса (необязательно).
2. **Образцы** — `samples/<имя>.docx` или `.pdf` (вымышленные данные!) и рядом `<имя>.expected.json` с ожидаемыми
   значениями полей (формат — `tests/test_form_samples.py`). Тест проверяет образцы всех модулей сам.
3. **Особая логика** (необязательно) — `hooks.py`: функции с известными именами, ядро вызывает их само
   (`formspec.HOOKS`): `after_text(ex, text, form, conf, source)` — после чтения полей из текста;
   `scan_page(page, lines, page_text, form, prefer)` — на скане, после чтения полей из текста страницы. Пример —
   раздел «новому Администратору» у REG.RU.
4. **Тип заявления** в `config/case_types.yaml`: `form: <id>`, список проверок `checks:` и правила вердикта
   (см. USAGE, раздел 3).
5. **Проверка:** `python -m doctool validate` (ошибки в описании, подписях `reference:`, `hooks.py`, образцах; список
   модулей — `--list`) и `python -m pytest tests -q`.

Описание бланка одним файлом `forms/<id>.yaml` (как до 0.7.3) тоже читается.

Новая **проверка** — функция с `@register(...)` в `doctool/compare.py` (или своём модуле, подключённом в `checks._load`): в декораторе указываются id, название проверки и строка таблицы. Затем её id добавляется в `checks:` нужных типов. Таблица, «Подтверждаю», правила вердикта и отчёты подхватывают её сами.

Новый **тип значения** поля — функция с `@field_type("имя")` в `doctool/application.py`.

Отладочная картинка с найденными подписями и областями сохраняется в `results/<дело>/crops/<файл>__regions.jpg`.

## Ограничения и точность (по тестовым образцам)

- **Электронные заявления (PDF/DOCX):** поля извлекаются практически без ошибок.
- **Паспорт со сканера и MRZ:** все ключевые поля берутся из MRZ с проверкой контрольных цифр. «Кем выдан» и место рождения распознаются OCR.
- **Паспорт без MRZ или фото с телефона:** ФИО и даты обычно распознаются. Отдельные поля, например дата выдачи под печатью, могут не прочитаться и тогда помечаются для ручной проверки. При сверке учитываются все варианты прочтения серии/номера.
- **Рукописные заявления:** без VLM поля не распознаются, в отчёт попадают фрагменты для ручной сверки. С Qwen3-VL 4B цифры читаются хорошо, а в фамилиях бывают ошибки (например, «Р» читается как «Т/Г»). Поэтому всё рукописное, что не совпало с паспортом, получает статус «нужна ручная проверка», а не «расхождение».
