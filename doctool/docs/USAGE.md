# PySimpleManager — руководство пользователя

> С версии 0.7.1 программа называется **PySimpleManager** (раньше — doctool). Внутренние имена не менялись: пакет и команды `python -m doctool …`, файл `doctool_web.bat`, папка расширения `doctool_extension`, схема выгрузки `doctool.case.v1`.

Версия 0.8.3. Установка описана в `README.md` (установщиком или из исходников). Здесь собраны все режимы работы, параметры, правила вердикта, формат выгрузки и решения типичных проблем.

---

## 1. Быстрый старт

Программу можно запускать двумя способами. Логика проверки одинаковая.

| Способ | Как запустить | Когда удобно |
|---|---|---|
| **Веб-интерфейс** | ярлык «PySimpleManager» (установленная программа, 0.7.5), двойной щелчок по `doctool_web.bat` или `python -m doctool web` — откроется браузер | обычная работа; при желании можно открыть коллегам в локальной сети |
| **Командная строка** | `python -m doctool check -a заявление.pdf -p паспорт.pdf` | пакетная обработка, скрипты |

Для веб-интерфейса нужны дополнительные пакеты: `pip install -r requirements-web.txt`. Окна приложения (Qt) с 0.7.4 нет.

Все команды запускаются **из папки, где лежат подпапки `doctool`, `forms` и `config`**. Файлы `.bat` сами переходят в нужную папку.

**Установленная программа (установщик, с 0.7.5).** Запуск — ярлык «PySimpleManager»: открывается браузер, окно консоли остаётся, пока программа работает; закрыли окно — программа остановилась. Повторный запуск, пока программа работает, просто открывает её страницу. Командная строка та же, вместо `python -m doctool` — `PySimpleManager.exe` (Windows, папка `%LOCALAPPDATA%\Programs\PySimpleManager`) или `pysimplemanager` (Linux): `PySimpleManager.exe check -a заявление.pdf`. Результаты и свои настройки — в «Документы\PySimpleManager» (раздел 4.1).

## 2. Работа в веб-интерфейсе

### 2.1. Вкладки (с 0.8.1)

Вкладки веб-интерфейса: **«Рабочее место»** (2.7) — заявления из тикетницы; **«Домены в manager»** (2.5) — данные
доменов списком; **«Смена владельца ЛК»** (2.5а). Прежней формы «Новая проверка» (заявление + паспорт, таблица полей,
ручной ввод, «Пересчитать») с 0.8.1 нет: отдельное заявление проверяет команда `check` (5.1); флаги 2.2–2.2а — её ключи.

### 2.2. Флаги документов

| Флаг | Что меняется в обработке |
|---|---|
| Заявление: **Авто** | программа сама определит: есть текстовый слой — читает текст, нет — распознаёт как скан |
| Заявление: **Электронное** | читать только текстовый слой (PDF из Word, DOCX); если его нет — обработать как скан |
| Заявление: **Скан** | всегда распознавать изображение, даже если в PDF есть текстовый слой |
| Заявление: **Фото** | как скан, плюс попытка выровнять перспективу (если границы листа видны) |
| Заявление: **Рукописное** | заполненные поля читает локальная модель (qwen). Без флага рукописные поля попадут в таблицу только фрагментами для ручной сверки |
| Заявление: **Поля заявления — нейросетью** (с 0.7.0) | поля читает текстовая нейросеть (по умолчанию `qwen3:8b`) вместо шаблона бланка (регулярок). Без галки — шаблон: для типовых печатных заявлений этого достаточно. Подробно — 2.2а |
| Паспорт: **Авто / Скан** | обычная обработка; у небольших изображений включается дополнительный проход с увеличением |
| Паспорт: **Фото** | выравнивание перспективы + дополнительный проход с увеличением мелкого текста |
| Паспорт: **Дочитывать моделью** | поля, которые OCR не распознал или распознал неуверенно, дочитывает локальная модель. Значения из MRZ она не меняет |

Ключи `check`: `--app-mode`, `--handwritten`, `--passport-mode`, `--vlm`, `--llm-fields` (раздел 5.1).

### 2.2а. Поля заявления — нейросетью (с 0.7.0)

С 0.8.1 — только ключ `--llm-fields МОДЕЛЬ` команды `check` (в веб-интерфейсе галки нет).

- **Без галки** поля читаются по шаблону бланка (подписи бланка `reference:` и регулярные выражения `text:` в `forms/<id>/form.yaml`), как раньше. Это
  быстро и предсказуемо для типовых печатных заявлений на бланке REG.RU.
- **С галкой** текст заявления (текстовый слой или распознанный скан) читает нейросеть из поля «Модель для полей».
  - Нужна Ollama и скачанная модель: `ollama pull qwen3:8b`.
  - Модель «рассуждает» перед ответом, на GTX 1070 это 1–1,5 минуты на заявление, предел — 4 минуты. Не уложилась
    с рассуждением — повтор без него.
  - Галка нужна для заявлений в свободной форме, на бланке нотариуса и для новых типов заявлений: их можно описать
    в YAML бланка словами, без регулярок.

Что не меняется: тип заявления по-прежнему определяется по ключевым словам, паспорт читается как раньше, рукопись —
моделью для рукописи (флаг «Рукописное»).

Как программа проверяет ответ нейросети:

- нейросеть возвращает дословную цитату из текста, и программа ищет её в документе. Значение — всегда кусок
  самого документа. Цитаты нет в тексте → значение «нужно проверить вручную» (источник `llm-…?`);
- отбрасывается:
  - печатный текст бланка («Primary, Secondary DNS»);
  - «ФИО» без имени и отчества;
  - ИНН не из 12 цифр (номер паспорта);
  - ФИО у подписи, скопированное из «Я, …»;
  - новый администратор, совпадающий с заявителем;
- «кем выдан» дополняется до границ (от «выдан» / даты до даты / кода подразделения);
- домены сверяются с прежним разборщиком по строкам списка. Пропущенный нейросетью домен добавляется и помечается
  «прочитаны по-разному».

Если Ollama или модель недоступна, поля читаются шаблоном бланка. В замечаниях дела это написано.

В отчёте источник значения — `llm-text` / `llm-ocr-text`. В `export.json` — `application_fields_reader`:
`regex` или `llm:<модель>`. В папке дела — `llm_debug.json`: что получила и ответила нейросеть, что отброшено, время.

Модель для рукописи и модель для полей на 8 ГБ видеопамяти одновременно не помещаются. Если включены обе, Ollama
переключает их, и это добавляет секунды. Можно выбрать одну модель для обоих полей, например `qwen3-vl:8b-instruct`.
Её качество на полях заявления не проверялось.

### 2.3. Данные администратора

С 0.5.0 блока ручного ввода данных администратора в интерфейсе нет: данные текущего администратора берутся из manager автоматически (раздел 2.5 и `MANAGER.md`). В командной строке ключ `--admin ФАЙЛ.json` остался для совместимости (проверки «Заявитель — текущий администратор», «Паспорт в системе устарел»).

### 2.4. Общий файл: заявление и паспорт вместе

Каждая страница классифицируется автоматически. Страница с бланком заявления (по ключевым фразам из `forms/<id>/form.yaml`) считается заявлением, разворот паспорта — паспортом. Нераспознанные страницы после паспорта (прописка, ранее выданные паспорта) тоже относятся к паспорту.

**Многостраничный файл заявления** (с 0.5.0, и без флажка «в одном файле»). Страница бланка ищется по заголовку («… о передаче права администрирования домена другому лицу») — перед ней бывают конверт и опись. К ней добавляются страницы-продолжения: вторая страница списка доменов, раздел «новому Администратору» (признаки — `detect.continuation` в `forms/<id>/form.yaml`). Нотариальная надпись, конверт и т. п. пропускаются. Если в файле два заявления одного заявителя с разными доменами, домены объединяются (замечание «В файле 2 заявления: домены объединены (37 + 19)»). Если среди страниц есть паспорт, в замечаниях будет подсказка отметить «Заявление и паспорт в одном файле».

**Заявления, у которых OCR потерял подписи таблицы, и заявления в свободной форме** (бланк нотариуса и т. п.) разбираются по тексту страницы:

- шапка: «от …» после оттиска штампа, ФИО в порядке «Имя Отчество Фамилия», дата рождения на следующей строке, через «д/р» или прописью («27 апреля 1988 года»);
- «Я, …» — без «прошу передать права…», с отчеством на следующей строке;
- паспорт — после «Паспорт», «Серия», с «№»; дата выдачи — после «Дата выдачи:» или первая дата после номера; номер после «ИНН», «ОГРН», «КПП» паспортом не считается;
- раздел «новому Администратору» целиком (`new_admin_block` в YAML): организация, ФИО, e-mail и телефоны — даже без подписей «Для физ.лиц и ИП:», «ФИО». Если на странице целиком таблицы не видно, раздел распознаётся ещё раз отдельно.

Поле, которое на скане похоже на рукопись (часто — печатный текст под штампом или подписью), при выключенной модели берётся из текста страницы, но как ненадёжное: проверка даст «нужна ручная проверка», а не «расхождение».

### 2.5. Данные доменов из manager

Вкладка **«Домены в manager»** и окно «Домены» рабочего места: кнопка **«Загрузить данные из manager»**. Данные читает расширение Chrome «PySimpleManager» из папки `doctool_extension`. Установка, что показывается, как влияет на вердикт и что делать при ошибках — **[MANAGER.md](MANAGER.md)**.

Проверки, которые добавляются к делу: «Домены в manager», «Заявитель — администратор доменов (Sd)», «Паспорт в Sd», «Администратор у доменов один». Данные доменов попадают в отчёт (раздел «Домены в manager») и в `export.json` (`manager_domains`).

**Порядок доменов в таблице и в отчёте — по «проблемности»** (с 0.4.0), с заголовком группы и числом доменов в ней:

1. свободен по WHOIS — домена нет в реестре;
2. данные в Sd не сходятся с документами (ФИО, дата рождения, паспорт, ИНН);
3. нет в manager — занят у другого регистратора или WHOIS не проверялся;
4. данные из manager не получены (ошибка, таймаут, проверка остановлена);
5. нужна ручная сверка (домен на юрлицо, неуверенное сходство ФИО);
6. мелкие расхождения (дата выдачи, кем выдан);
7. к сведению (например, в Sd прежний паспорт);
8. найден, сверка не выполнялась (данные загружены без проверки дела);
9. в порядке.

Внутри группы — порядок заявления. В `export.json` порядок доменов прежний — как в заявлении.

**ЕСИА** (с 0.6.0; юрлица — с 0.7.2: ИНН, КПП, название с организационно-правовой формой, улица, дом и индекс юридического адреса). У доменов физлиц и юрлиц — колонка «ЕСИА» (поле `state` со страницы «Идентификация через Госуслуги», открытой по ссылке со Sd домена, и итог сверки Sd с файлом данных ЕСИА) и кнопка **ESIA** рядом с Sd / S — окно сверки. На вердикт не влияет. В `export.json` у домена — `esia` (state, ссылки, поля из файла ЕСИА), `esia_rows`, `esia_status`. Подробно — MANAGER.md, раздел 3.

### 2.5а. Смена владельца ЛК (с 0.6.0)

Вкладка **«Смена владельца ЛК»**: аккаунт (номер, «Данные пользователя #…», логин или домен; (0.8.1) e-mail аккаунта — поле «E-mail» «Данных пользователя», с логином может не совпадать) → базовая анкета и обслуживающая организация из manager → сверка с данными заявления (пока вручную) → форма нового владельца и кнопка **«Заполнить автоматически»**: программа открывает вкладку «Базовая анкета пользователя #…» в Chrome и вписывает поля; «Сохранить» нажимает оператор. Физлица, с 0.7.3 — ИП и юрлица: сверка базовой анкеты юрлица (название, ИНН, КПП, физический и почтовый адрес, телефон, e-mail) и ИП (как физлица + ИНН ИП), формы нового владельца-ИП и юрлица; если тип анкеты в manager другой, программа переключает его на странице. Подробно — MANAGER.md, раздел 5.

### 2.6. Веб-интерфейс: доступ из сети

По умолчанию интерфейс доступен только на этом компьютере: `http://127.0.0.1:8765`. Чтобы открыть его коллегам, запустите `python -m doctool web --host 0.0.0.0`. Документы всё равно обрабатываются на компьютере, где запущена программа, но станут доступны по сети. Делайте так только во внутренней сети и с согласия ответственных за безопасность.

### 2.7. Рабочее место (с 0.7.6)

Вкладка **«Рабочее место»** — одно окно на всё заявление из тикетницы: документы, домены, manager, строка таблицы,
«Поиск». Нейросеть не нужна.

**1. Приём.** Впишите номер тикета (кнопка «Вставить» — из буфера обмена), выберите тип операции и способ
получения, перетащите в окно архив из тикетницы (zip, rar, 7z) или сами файлы. Программа распаковывает архив
(русские имена файлов из Windows-архивов читаются правильно; архив в архиве тоже), делает из каждой страницы
PDF, фото, многостраничного TIFF и DOCX (и фото, вставленных в Word) отдельную страницу и раскладывает их по
группам ленты вверху: **Заявление**, **Паспорт**, **Прочее** (конверт, опись, нотариус), **Не определено**,
**Скрытые** (пустые страницы и повторы). Подпись `.sig` показывается отдельно — только ссылка, проверяется вручную.
Для rar и 7z нужен 7-Zip: в установщике для Windows он внутри; в Linux — пакет `7zip` (для rar — ещё `unrar`).
(0.8.1) **«Без файлов — открыть рабочее место»** — сразу к окнам; архив или файлы можно потом перетащить на рабочее
место (или «Добавить файлы» в шапке дела): разбираются только новые страницы, проверка запускается заново.

**2. Если страницы разложены неправильно** — перетащите миниатюру в нужную группу (или прямо в окно документа),
поверните страницу (↻), а если паспорт сфотографирован на одном листе с заявлением — кнопка **«⬚ Рамкой →
паспорт»** и обведите его мышью. Затем **«Перепроверить»**: документы прочитаются заново по новым страницам.

**3. Окна.** Заявление, паспорт, домены, строка таблицы — отдельные окна: двигаются за заголовок, меняют
размер за любой край, прилипают к краям и друг к другу; к левому или правому краю экрана — половина, в угол —
четверть, к верху — во весь экран; двойной щелчок по заголовку — развернуть. Раскладки — на панели над окнами;
«Запомнить мою» — своя раскладка для каждого типа операции. **«Разложить»** — каждая страница документа в своём окне;
кнопка ⧉ в заголовке — открепить документ в отдельное окно браузера (например, на второй монитор). Масштаб страницы —
кнопки или Ctrl + колесо мыши, сдвиг — мышью. (0.8.1) Текст страниц PDF с текстовым слоем выделяется мышью и
копируется (Ctrl+C), как в браузере; у сканов текста нет. (0.8.3) **«▴ Убрать панель»** (Ctrl+Shift+↑) — верхняя
панель уезжает наверх, окна документов растут; вернуть — «▾ Панель» в оставшейся полосе (Ctrl+Shift+↓). В полосе —
тикет, операция, шаги, «Поиск», «Окна» и свёрнутые окна.

**4. Сверка** — по документам глазами: окна «Сверка» и отметок Госуслуг с 0.8.1 нет; «Госуслуги · паспорт» — в строке
«Поиск» (п. 8).

**5. Домены.** Карточки доменов из manager: администратор и дата рождения, (0.8.0) серия и номер паспорта с датой
выдачи и «кем выдан» (у организации — ИНН; «в поиск» — вписать в строку «Поиск»), ЕСИА, последняя смена администратора,
provider, номер аккаунта, **логин** и (0.8.1) **e-mail аккаунта** (поле «E-mail» «Данных пользователя»); буква **«К»** — в S есть комментарий администратора (щелчок — окошко с текстом
и «Копировать»); проверки домена — «стоп», «внимание», «к сведению» (настраиваются в `config/workspace.yaml`).
Снимите галку у домена, который не участвует в смене. Кнопка **Sd** — окно с полями Sd и S. Несколько доменов — можно
поправить список и нажать «Загрузить из manager».

**6. Смена в manager.** (0.8.2) Кнопка **«Смена админа через manager»** (справа внизу, при любом типе операции)
сначала покажет, что осталось: «стоп» по домену, вердикт программы «Отклонить»; открыть всё равно можно, указав
причину (сохранится в деле). Пустой список доменов причины не требует — поле «Домены» на странице manager тогда не
трогается. В окне manager: **шаг 1** — домены, смена администратора, перенос на другой аккаунт (номер договора из
заявления), документы для загрузки (подпись по умолчанию не загружается) → «Вписать на странице manager»; проверьте
страницу и нажмите «Далее» сами. **Шаг 2** — «Сверить "данные нового аккаунта"»: программа прочитает страницу и
подсветит поля там же (зелёный — как в заявлении, красный — нет); «Заполнить вручную: ФИО и контакты» — для нового
администратора без аккаунта. После сообщения об успехе — «Смена выполнена → строка таблицы».

**6а. Безбумажные операции** (0.8.2). Кнопка **«Безбумажные операции»** рядом — окно доверенности: поля страницы
manager «Добавить новый документ от пользователя» (Документы → Доверенности → Добавить) под теми же названиями:
физлицо — номер паспорта и ФИО администратора, юрлицо — код страны (RU) и ИНН компании; e-mail и телефон. Значения
берутся из Sd найденного домена (окно «Домены»; у доменов с разными администраторами — выбор), иначе паспорт и ФИО из
документов дела; их можно поправить. «Вписать на странице manager» — расширение открывает страницу и вписывает поля.
Вид документа и срок действия выбираете вы; «Показать домены, на которые будет выдана доверенность» и «Добавить
документ» — тоже вы. Затем «Документ добавлен → строка таблицы».

**7. Строка таблицы (xlsx).** Колонки: дата · принял · обработал · домен (смена администратора, корректировка данных
домена, безбумажные операции) или номер договора (смена владельца аккаунта, восстановление доступа, деактивация номера) · тип операции ·
способ получения · **номер тикета и статус** одним полем («#20261012373031821 готово»). Все поля можно поправить;
изменённое поле подсвечено, ↺ — вернуть как было. «Принял» — ваша фамилия, запоминается; «обработал» — по
умолчанию тот же человек. Несколько доменов — через запятую или галка «строка на каждый домен». «Копировать строку»
и вставьте в таблицу (Ctrl+V) — колонки разойдутся сами. Файлы в Nextcloud программа не трогает.

**8. Строка «Поиск» (с 0.8.0).** Кнопка **«Поиск»** на панели над окнами или **Ctrl+K** — строка запроса над окнами;
та же кнопка, Ctrl+K или Esc — убрать. Впишите запрос или щёлкните значение дела в списке под строкой (ФИО, серия и
номер паспорта, дата рождения, ИНН, домены, новый администратор, договор; Shift+щелчок — добавить к запросу) и
выберите сервис: **Google** (Enter), **ЕГРЮЛ** (Shift+Enter) — расширение откроет egrul.nalog.ru и впишет
запрос в поле поиска, «Найти» нажимаете вы; **Госуслуги · паспорт** — откроет «Проверка действительности паспорта» и
впишет серию, номер, фамилию и имя («Продолжить» нажимаете вы): из строки запроса, если там серия и номер
(«4012 654321 Иванова Анна»), иначе из паспорта (заявления) дела, иначе из Sd найденного домена. Рядом — быстрые ссылки:
**Nextcloud**, **Проверка ЭП · Госуслуги**, **Контур.Крипто**. Сайт открывается **рядом с рабочим местом**:

- «рядом (авто)» — во второй половине окна Chrome (разделённый экран): слева программа, справа сайт, разделитель
  тянется мышью. Расширение делает это само в Chrome 155 и новее; в Chrome 145–154 соберите пару один раз вручную
  (правый щелчок по вкладке программы → разделённый экран) — дальше сайты открываются во второй вкладке пары. Иначе —
  окном справа;
- «окном справа» — отдельное окно Chrome на правой части экрана, окно программы сдвигается влево;
- «вкладкой» — обычная соседняя вкладка.

Способ выбирается в строке поиска (запоминается в браузере). Следующий запрос открывается там же — вкладки не
копятся. «Убрать» оставляет вкладку сайта (она выходит из разделённого экрана) или сворачивает окно — снова
«Поиск» возвращает сайт на место без перезагрузки. Без расширения сайт открывается обычным окном браузера, а запрос
для ЕГРЮЛ копируется в буфер обмена. Запросы сохраняются в деле — список под строкой, щелчок открывает снова.

**Файлы дела на сайт.** Перетащите файл из строки «Файлы:» в строке поиска, из ленты страниц (миниатюра — файл этой
страницы) или из списка «Подпись и другие файлы» на страницу проверки ЭП, Контур.Крипто или Nextcloud в другой
половине окна — расширение возьмёт файл у программы и положит его на страницу, как если бы его перетащили из папки
(если страница не принимает перетаскивание — в поле выбора файла). Кнопки «Проверить», «Расшифровать», «Загрузить»
на сайтах нажимаете вы. На другие сайты файлы так не переносятся.

**9. Окна (с 0.8.0).** Кнопка **«Окна ▾»**: список всех окон рабочего места с их состоянием (открыто, свёрнуто,
закрыто, откреплено) — щелчок открывает любое, в том числе Sd каждого домена и окно manager. **«Показать все»** —
вернуть все свёрнутые окна на их места (раскладка не применяется, окно заявления не сдвигается); «Sd всех доменов».

**10. Недавние дела** на экране приёма открывают дело снова со всеми отметками. С 0.8.0 — **«Удалить»** у дела и
**«Удалить все»**: после подтверждения папка дела (файлы, страницы, отметки) и папки результатов его проверок
стираются с диска. Дело, которое ещё разбирается, не удаляется.

Дела рабочего места хранятся в `results/_workspace/` (у установленной программы — в «Документы\PySimpleManager»).
Результаты проверки — как обычно, в папке дела в `results/`.

**Настройки** — `config/workspace.yaml` (свой файл можно положить в папку данных `config/`): типы операций и что
пишется в 4-й колонке, способы получения, статус по умолчанию, логины manager → фамилии, проверки доменов и их
уровень (`stop` — смена в manager только с причиной, `warn`, `info`, `off`); (0.8.0) раздел `search` — где
открывается сайт по умолчанию, ширина окна справа, сервисы строки «Поиск» (адрес с `{q}`, `fill: egrul` — вписать
запрос в форму) и быстрые ссылки. Проверить файл — `python -m doctool validate`.

## 3. Вердикт и типы заявлений

Типы заявлений и правила вердикта описаны в **`config/case_types.yaml`**. Их можно менять без программирования.

```yaml
admin_change_person:
  title: Смена администратора домена (физлицо → другое лицо)
  form: regru_transfer_person      # модуль заявления forms/<id>/
  enabled: true
  checks: [fio_header, fio_text, birth_date, passport_number, domains, …]   # какие проверки выполнять
  rules:
    reject:                        # любое сработавшее → «Отклонить»
      - when: {flag: old_passport}
        reason: В заявлении указан прежний (недействительный) паспорт
      - when: {check: "Серия и номер паспорта", status: [fail]}
        reason: Серия и номер паспорта не совпадают с предъявленным паспортом
    review:                        # любое сработавшее → «Ручная проверка»
      - when: {any_status: [review]}
        reason: Есть поля, которые нужно подтвердить вручную
```

Если не сработало ни одно правило, вердикт — «Принять».

Условия в `when` (несколько условий в одном `when` должны выполниться одновременно):

| Условие | Значение |
|---|---|
| `check: "<название>"`, `status: [...]` | у проверки с таким названием один из статусов `ok`, `warn`, `fail`, `review`, `info` |
| `any_status: [...]` | хотя бы у одной проверки такой статус |
| `missing: <поле или роль>` | поле заявления пустое: имя поля из `forms/<id>/form.yaml` или его роль (`applicant_fio`, `domains`…) |
| `flag: old_passport` | указан прежний паспорт (см. ниже) |
| `flag: admin_mismatch` | заявитель не текущий администратор или домены не его (нужны данные из системы) |

Названия проверок — в разделе 7, на вкладке «Все проверки» и в `python -m doctool validate --list`.

**Какие проверки выполняются** — список `checks:` у типа заявления (id из реестра `doctool/checks.py`; список с названиями — `validate --list`). Порядок проверок в отчёте задаёт реестр, а не этот список. Если `checks:` не указан, тип с бланком получает все проверки, тип без бланка — только проверки паспорта и данных из системы/manager. Правило `check:` по проверке, не включённой в `checks:`, не сработает никогда — такие правила показывает `python -m doctool validate`.

**Как определяется «прежний паспорт».** Правило срабатывает, если серия и номер в заявлении не совпадают с предъявленным паспортом и при этом выполняется одно из условий:

- номер из заявления найден на странице паспорта «Сведения о ранее выданных паспортах» — это прямое доказательство;
- ФИО или дата рождения совпадают, и дата выдачи в заявлении раньше даты выдачи предъявленного паспорта. Если номер в заявлении прочитан из рукописи, ставится не «отклонить», а «ручная проверка».

Стартовые правила — это предложение. Сверьте их с регламентом и поправьте в `case_types.yaml`. Новый тип заявления добавляется так: бланк описывается модулем `forms/<id>/` (README, «Как добавить новое заявление»; поля сопоставляются проверкам через `role:`), а тип — в `case_types.yaml` со ссылкой `form: <id бланка>` и списком `checks:`. После правок — `python -m doctool validate`.

## 4. Выгрузка для внутренней системы

### 4.1. Файлы дела

Каждая проверка создаёт папку `results/<дата_время>_<дело>/`:

| Файл | Содержимое |
|---|---|
| `report.html` | отчёт: вердикт, проверки, все поля с источником и уверенностью, фрагменты рукописи |
| `export.json` | **выгрузка для автозаполнения** (схема `doctool.case.v1`, см. ниже) |
| `result.json` | всё распознанное: поля заявления и паспорта со всеми подробностями, проверки, замечания |
| `crops/` | фрагменты полей скана заявления и `…__regions.jpg` — разметка бланка для настройки форм |

**Где папка `results`.** Запуск из исходников — в текущей папке (папке программы), как раньше. Установленная программа (0.7.5) — `Документы\PySimpleManager\results`. Путь печатается при запуске веб-интерфейса; свой — `-o папка` или переменная `DOCTOOL_HOME` (раздел 9).

**Папка данных установленной программы** — `Документы\PySimpleManager` (или `DOCTOOL_HOME`):

| Что | Зачем |
|---|---|
| `results\` | дела и `реестр_проверок.xlsx` |
| `forms\<id>\` | свои модули заявлений (необязательно). Модуль с тем же id, что у встроенного, заменяет встроенный; новый id — добавляется |
| `config\case_types.yaml` | свои типы заявлений и правила (необязательно). Если файла нет — встроенные. Пока лежит своя копия, правила из новых версий к вам не попадают |
| `ПРОЧТИ.txt` | то же кратко + где лежат встроенные модули и правила (их можно скопировать как образец) |

Обновление и удаление программы эту папку не трогают.

Кроме того, в `results/реестр_проверок.xlsx` добавляется строка на каждую проверку. Если реестр открыт в Excel, данные запишутся в отдельный файл с датой в имени. После «Пересчитать» файлы дела перезаписываются, а в реестр новая строка не добавляется.

## 5. Командная строка

```
python -m doctool [общие параметры] <команда> [параметры команды]
```

| Общий параметр | Назначение |
|---|---|
| `--vlm МОДЕЛЬ` | локальная модель Ollama, напр. `qwen3-vl:4b-instruct` |
| `--ollama АДРЕС` | адрес Ollama (по умолчанию `http://127.0.0.1:11434`) |
| `-q`, `--quiet` | не показывать ход работы |
| `--llm-fields МОДЕЛЬ` | (0.7.0) поля заявления читает нейросеть, напр. `qwen3:8b` (как галка «Поля заявления — нейросетью»); для `web` — модель по умолчанию для галки |
| `--llm-think on\|off` | нейросеть для полей рассуждает перед ответом (по умолчанию `on`: точнее, но дольше) |

Общие параметры пишутся **до** команды: `python -m doctool --vlm qwen3-vl:4b-instruct check ...`

### 5.1. `check` — проверка с вердиктом

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `-a`, `--application` | — | файл заявления (с `--combined` — общий файл) |
| `-p`, `--passport` | — | файл паспорта |
| `--combined` | выкл. | заявление и паспорт в одном файле `-a` |
| `-t`, `--case-type` | `admin_change_person` | тип заявления из `config/case_types.yaml` |
| `--app-mode` | `auto` | `auto` / `electronic` / `scan` / `photo` |
| `--handwritten` | выкл. | заявление заполнено от руки (вместе с `--vlm`) |
| `--passport-mode` | `auto` | `auto` / `scan` / `photo` |
| `--admin ФАЙЛ.json` | — | данные текущего администратора из системы |
| `-o`, `--out` | `results` | папка результатов |
| `--case` | имя файла | название дела |

Нужно указать хотя бы `-a` или `-p`.

```
:: электронное заявление + скан паспорта
python -m doctool check -a %D%\set1\ApplicationSet1.pdf -p %D%\set1\PassportSet1.pdf --case Попова

:: рукописное заявление + фото паспорта, с моделью
python -m doctool --vlm qwen3-vl:4b-instruct check -a заявление.jpg --handwritten -p паспорт.jpg --passport-mode photo

:: всё в одном PDF, с данными администратора из системы
python -m doctool check -a комплект.pdf --combined --admin admin.json

:: только паспорт
python -m doctool check -p паспорт.pdf -t passport_only
```

### 5.2. `extract` — только извлечь поля (JSON в консоль)

```
python -m doctool extract паспорт.pdf --type passport
python -m doctool extract заявление.pdf
python -m doctool extract паспорт.pdf --type passport > passport.json
```

### 5.3. `validate` — проверить описания бланков и типов заявлений

```
python -m doctool validate          # ошибки в модулях forms/ и config/case_types.yaml
python -m doctool validate --list   # плюс: все проверки (id, названия, строки таблицы), роли полей, типы заявлений
```

Сначала печатает, какие папки и файлы использует программа: папку данных, модули заявлений (свои и встроенные), файл правил (0.7.5).

Находит: неизвестный `type` или `role` поля, две роли у разных полей, ошибки в регулярных выражениях, `scan` без `anchor`/`region`, тип заявления со ссылкой на несуществующий бланк, неизвестный id в `checks:`, правило с названием проверки, которой нет или которая не включена в `checks:` этого типа, неизвестные флаги и статусы. Tesseract для этой команды не нужен. Запускайте после каждой правки YAML.

### 5.4. `whois` — статус домена в реестре

```
python -m doctool whois example.ru пример.рф
python -m doctool whois example.ru --raw        # с ответом сервера целиком
```

Запрос идёт на WHOIS-сервер реестра (порт 43; для .RU/.SU/.РФ — whois.tcinet.ru). Если порт закрыт в сети, будет «WHOIS недоступен».

### 5.5. `web` — веб-интерфейс

```
python -m doctool web  [--port 8765] [--host 127.0.0.1] [--no-browser] [-o папка]
python -m doctool --vlm qwen3-vl:8b-instruct web      # модель по умолчанию для интерфейса
```

Команды `gui` (окно Qt) с 0.7.4 нет.

С 0.7.5: если на этом порту уже работает PySimpleManager, второй экземпляр не запускается — открывается страница работающего. Если порт занят другой программой — сообщение «Порт … занят другой программой» (запустите с `--port`).

## 6. Поддерживаемые файлы

| Формат | Заявление | Паспорт |
|---|---|---|
| PDF с текстовым слоем | поля читаются из текста | — |
| PDF-скан | первая страница заявления | весь паспорт: разворот с фото ищется среди первых 4 страниц, остальные — для «ранее выданных» |
| JPG, PNG, BMP, TIFF, WEBP | да (у многостраничного TIFF — первая страница) | да |
| DOCX | да | — |
| ZIP, RAR, 7Z (рабочее место, с 0.7.6) | распаковываются; файлы внутри — как выше | |

Поворот страниц на 90° и 180° определяется автоматически.

**Как читается заявление с текстом (PDF из Word, DOCX), с 0.7.3.** Если документ заполнен по бланку (печатные подписи
бланка на месте — «(ФИО, дата рождения)», «(кем выдан)»…), значения берутся между подписями (`reference:` в описании
бланка). Если нет (свободная форма, бланк нотариуса, изменённая вёрстка) или значение поля не разобралось — по
регулярным выражениям бланка, как раньше. Как прочитано, видно в `export.json`: `application_fields_reader` —
`reference` (по подписям бланка), `regex` (регулярками), `manual` (введено вручную), `llm:<модель>`.

- DOCX читается в порядке документа: таблица (например, нового администратора) стоит на своём месте, а не после
  подписи, как было до 0.7.3; объединённая ячейка — один раз.
- PDF, где значения вписаны поверх бланка в PDF-редакторе (поля формы, надписи), читается по расположению на
  странице: значение оказывается рядом со своей подписью. Обычный PDF — как раньше.

## 7. Что проверяется

| Проверка | Как |
|---|---|
| ФИО в шапке / в «Я, …» / у подписи ↔ паспорт | с учётом падежа и инициалов. Явная опечатка OCR в имени/отчестве паспорта («РИКТОРОВИЧ») не считается расхождением |
| Дата рождения, серия и номер, дата выдачи | точное совпадение; учитываются все варианты прочтения паспорта |
| Кем выдан | нечётко, сокращения раскрываются (ОВД, ОУФМС, г., обл., р-на…). В режиме «Только проверка паспорта» сверять не с чем — оценивается само прочтение: распознано ли, похоже ли на название органа, надёжен ли источник (модель или OCR с уверенностью < 0,6 → ручная проверка). Явные опечатки OCR в словах бланка правятся («РООСИИ» → «РОССИИ», «МОСКОВСКОЙ ВЛАСТИ» → «… ОБЛАСТИ»), исходное прочтение сохраняется в вариантах |
| Кем выдан ↔ код подразделения | регион из названия органа («… ПО МОСКОВСКОЙ ОБЛАСТИ», «… ГОРОДА КАЛУГИ») сравнивается с регионом по первым двум цифрам кода (500-050 → 50, Московская обл.). Не совпал — «проверить»; регион в названии не указан — «к сведению» |
| Кем выдан ↔ данные системы | если в данных администратора указано «Кем выдан» и в системе тот же паспорт |
| Паспорт приложен | паспорт не загружен → «нужна ручная проверка» («Паспорт не загружен — сверка с паспортом не выполнялась»). Срок действия паспорта по возрасту (20/45 лет) с 0.5.0 не проверяется — сверяется только сходство данных Sd, заявления и паспорта |
| Серия ↔ год выдачи | год бланка по 3–4-й цифрам серии. Бланки печатают с опережением: год серии на 1 больше года выдачи — норма («к сведению»), на 2–3 — «проверить», больше — «так не бывает». Дата выдачи из MRZ не отбрасывается никогда |
| MRZ | контрольные цифры |
| Указан прежний паспорт | см. раздел 3 |
| Заявитель — текущий администратор, домены администратора, паспорт в системе устарел | при наличии данных из системы |
| ФИО: шапка ↔ «Я, …» | согласованность внутри заявления |
| ИНН ИП | контрольные разряды |
| Домен(ы) | формат + punycode; учитываются рукописные «distobR-RU». Длинный список: имя, перенесённое на следующую строку после дефиса (`business-⏎dvd.ru`), склеивается (дефис входит в имя); на скане многострочный список распознаётся ещё раз отдельным абзацем. «Нужна ручная проверка», если число доменов не совпало с «всего N» из заявления, остались обрывки без доменной зоны («инфоклуб.»), в имени смешаны кириллица и латиница или прочтения OCR разошлись. Склеенные имена перечислены в комментарии проверки |
| Новый администратор | указан; совпадает с текстом над таблицей; не совпадает с заявителем |
| Контакты, договор/аккаунт | заполнены |
| Дата заявления | разбирается из текста прописью; не в будущем |
| Адрес регистрации | только показывается, со штампом прописки не сверяется |

**Статусы проверок:**

| Значок | Статус | Значение |
|---|---|---|
| ✓ | в порядке | совпадает / корректно |
| ! | проверить | мелкое расхождение или не заполнено |
| ✗ | расхождение | значения различаются |
| ? | нужна ручная проверка | рукопись, неуверенное распознавание или поле не найдено |
| · | к сведению | информация |

Если значение прочитано ненадёжно (рукопись, модель или низкая уверенность OCR), несовпадение получает «?», а не «✗».

## 8. Пакетная обработка

`check_all.bat` (лежит в папке программы): в папке `D` (с 0.6.0 — `Dataset\PhysicalPersonAdminChange`) по подпапке на дело:

- есть `Application*` и `Passport*` — заявление и паспорт;
- есть только `Passport*` — «Только проверка паспорта»;
- иначе — первый PDF / JPG / PNG папки как заявление (сканы-комплекты без отдельного паспорта).

Если в папке и заявление, и паспорт, но названы иначе (как в `set6`), переименуйте их в `Application…` и `Passport…` — иначе первый файл по алфавиту будет принят за заявление.

Итоги всех дел собираются в `results\реестр_проверок.xlsx`.

## 10. Типичные проблемы

| Сообщение / симптом | Решение |
|---|---|
| `Нужен Python 3.10 или новее` | `py -3.12 -m doctool ...` или активируйте `.venv` |
| `Tesseract не найден` / `нет языков: rus` | см. README, установка Tesseract |
| `No module named fastapi` / `uvicorn` | `pip install -r requirements-web.txt` |
| `No module named doctool` | запускайте из папки программы (или через `.bat`) |
| `error: unrecognized arguments: --vlm` | `--vlm` пишется до `check`/`web` |
| Модель недоступна / «Ollama не найдена» | запустите Ollama, скачайте модель: `ollama pull qwen3-vl:4b-instruct` |
| Веб: `Порт 8765 занят другой программой` / `address already in use` | `python -m doctool web --port 8780` (и тот же порт в настройках расширения) |
| «Система Windows защитила ваш компьютер» при установке | установщик не подписан сертификатом: «Подробнее» → «Выполнить в любом случае» |
| Окно установленной программы сразу закрывается | запустите `PySimpleManager.exe` из командной строки — будет видно сообщение (с 0.7.5 при ошибке окно ждёт Enter) |
| «manager: расширение не подключено» | см. [MANAGER.md](MANAGER.md), раздел 9 |
| Неверно разделены страницы общего файла | вкладка «Страницы» → поправить роли → «Перезапустить с этими страницами» |
| `Не найдена подпись поля «…»` | плохой скан или другая версия бланка: посмотрите `crops\…__regions.jpg` |
| `MRZ не найдена` | нормально для паспортов примерно до 2011 года |
| Долго идёт рукописное заявление | модель работает на процессоре: проверьте `ollama ps` (нужно `100% GPU`) |

## 11. Ограничения версии 0.2

- Настроен один бланк (REG.RU, передача права администрирования, физлицо). Остальные типы заявлений помечены «(скоро)».
- Правила вердикта стартовые — их нужно сверить с регламентом.
- Связь с внутренней системой: с 0.3.0 данные доменов (Sd, S) читаются из manager через расширение Chrome (см. MANAGER.md). С 0.6.0 — автозаполнение базовой анкеты физлица (смена владельца ЛК), с 0.7.3 — ИП и юрлица; остальные формы manager не заполняются, выгрузка — файлом `export.json`.
- Адрес регистрации не сверяется со штампом прописки.
- Выравнивание перспективы на фото срабатывает, только когда в кадре видны все четыре края документа.
- Рукопись: цифры и e-mail модель читает хорошо, фамилии — с ошибками. Поэтому рукописные поля нужно подтверждать по фрагментам.
- Старые паспорта (примерно до 2010 г.) часто заполнены от руки. Tesseract их не читает, значения даёт только модель (с флагом «Дочитывать моделью»). Такие значения всегда помечаются для ручной проверки: при расхождении ставится «?», а не «✗», и на них не строится отказ. Невозможные значения (например, дата выдачи раньше 01.10.1997 или раньше года бланка по серии) отбрасываются автоматически.
